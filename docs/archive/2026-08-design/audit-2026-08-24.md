## 二、架构合规审计（对照 CLAUDE.md 不可违反条款）

已达标：
- ProviderConfigStore / RefreshTrigger / DataEngine **无 slug switch**，协议差异全部 manifest 声明 ✅
- `builtin` 字段下沉 manifest，编辑弹窗按 `isBuiltin` 锁字段 ✅
- 特殊解析（glm JWT / oc-go cookie / ollama data-time）均在 provider 脚本侧 ✅

**残留违规 2 处**：

1. `FloatingView.swift:229-237` — `accent(_ st:)` 按 slug 硬编码品牌色：
   ```swift
   case "glm": return .blue
   case "ollama": return .green
   ...
   ```
   新增内置供应商会掉进 `default: .teal`，且此函数属于主框架 UI。**建议**：manifest 加可选字段 `"accent": "blue"`（hex 或系统色名），`accent()` 改查 manifest，缺省 `.accentColor`。

2. `HUDSync.swift:12` — `builtinKeys` 硬编码 5 个字符串。这是与 statusline.mjs 的 ENV_REGISTRY 共享契约，属跨进程耦合。**建议**：把该清单也放进各内置 manifest（如 `"statuslineKey": "CC-GLM"`），HUDSync 动态收集；或至少注释注明「与 statusline.mjs ENV_REGISTRY 同步维护」。

## 三、缺陷清单（按严重度）

### P0 — 会 crash / 功能失效

**P0-1 URL 强解包 crash**
`RefreshTrigger.swift:13` 与 `:23`：
```swift
var req = URLRequest(url: URL(string: config.queryUrl)!)
```
url 含空格/中文/非法字符时 `URL(string:)` 返回 nil，直接 crash 整个 App（菜单栏 App crash 无感知，用户只见图标消失）。
**修复**（3 行）：
```swift
guard let u = URL(string: config.queryUrl) else { return "url 非法" }
```

**P0-2 定时触发在无 testModel 时静默失效**
`DataEngine.swift:126` 调 `RefreshTrigger.testRefresh(config:)`，而 config 来自 `ProviderConfigStore.read`，`testModel` 为空时 POST body `"model": ""` —— 供应商拒绝，滚动窗口不推进。这正是之前在 `trigger()` 里修过的同类问题（`RefreshTrigger.swift:40-42` 有回退逻辑），**checkSchedules 漏改**。
**修复**：改调 `RefreshTrigger.trigger(manifest: st.manifest, authFile: authFile)`（一行替换，回退逻辑复用）。

### P1 — 逻辑错误 / 数据不一致

**P1-1 自定义供应商编辑改 url 不生效**
`EditForm.swift:222-230` 编辑分支只写 auth 文件 + 重写 fetch.sh，**不重写 manifest.json**。而 `ProviderConfigStore.read` 的 `queryUrl` 是 `manifest.queryUrl ?? auth.apiUrl`（`ProviderConfigStore.swift:33`），自定义供应商新建时已把 queryUrl 写进 manifest —— 之后用户在编辑弹窗改 url，manifest 还是旧值，上栏「测试」与查询永远打旧地址。fetch.sh 读 auth 文件所以余额查询倒是新的，**两套 url 悄悄分叉**。
**修复**：编辑分支对 `!isBuiltin` 供应商同步 `PluginGenerator.customManifest(name:config:authFile:)` + `writePlugin`（与新建分支同构）。

**P1-2 新建供应商 slug 冲突无检测**
`EditForm.swift:202` `slugify("GLM") == "glm"`，写进用户目录后 `ProviderRegistry.load` 用户源覆盖 bundle 源（`ProviderRegistry.swift:41`），**内置 GLM 被静默顶掉**。同理 `slugify("Ollama")` 顶掉 ollama。
**修复**：save 前检查 `ProviderRegistry.load(...).plugins.map(\.slug)` 含新 slug 则报错提示改名；或自动加后缀 `-2`。

**P1-3 gpt 供应商成「僵尸」状态**
`gpt/manifest.json` 无 `authFile` 也无 `builtin`：编辑按钮隐藏（`SettingsView.swift:102`）、contextMenu 编辑隐藏（`:30`）、删除按钮隐藏（`:109`，因非 builtin 本应显示删除——实际 `!isBuiltin` 为 true 会显示删除？核对：gpt 无 `builtin` 字段 → `isBuiltin == false` → **会**显示删除，但点删除只删用户目录（gpt 在 bundle，删不掉）→ `PluginGenerator.removePlugin` 对不存在路径会 throw，被 `try?` 吞掉 → 无任何反馈，违反自家「操作反馈」基线。
**修复**：gpt 要么补 `authFile`+`builtin`，要么在 manifest 加 `"enabled": false` 下线；删除按钮对 bundle 内置供应商一律不显示（现判据 `isBuiltin` 不含 gpt，判据应改为「插件目录在用户目录」）。

### P3 — 低优先

- `DataEngine.swift:115-129`：checkSchedules 每 10s 对每家做一次 auth 文件磁盘读。量小可接受；若做，reloadRegistry 时缓存 scheduleTimes 即可。
- `DataEngine.swift:210-228`：triggerAndRefreshAll 触发完立刻查余额，供应商计费若异步结算可能读到旧值（用户此前遇过「等 1 分钟」）。可在两阶段间 `Task.sleep(2s)`。
- `ProviderRunner.swift:64-77`：100ms 轮询等进程退出属 busy-wait，正确且简单，注明不动。
- `MenuBarView.swift:79`：`now: Date()` 在 body 求值时定格，倒计时靠 10s timer 重渲染推进——现状可用。
- 凭证明文存 auth 文件（600 权限）：与 `.claude` 目录同信任域，属合理决策，建议在 README「安全」节写明，不引入 Keychain（YAGNI）。

## 六、UI/UX 遗留（HIG 基线外）

1. **删除操作无确认**：`SettingsView.swift:168-172` 删除供应商立即执行（虽只影响用户目录，但含凭证文件）。建议 `.confirmationDialog`。
