## 1. 现状与根因

### 1.1 现状（按代码，不按上一版文档描述）

- 供应商管理由 `SettingsWindowManager` 的 NSWindow 承载；`ProviderManagerView` 选择布局，具体布局在 `ui/ProviderLayouts.swift`。`FloatingPanel.swift` 只是额度悬浮窗，本轮不改。
- **三种排布共享同一个旧独立编辑面板**：打开方式不同，底层都是 `ui/EditForm.swift`（466 行）。
- **新建与编辑走的是同一个 `EditForm`**，不是"新建一个 sheet、编辑内联"。
- **导入是 sheet** `ui/ImportSheet.swift`（147 行），与编辑不在同一层级。
- 编辑面板固定窄宽，内容超出时不滚动；底部无固定操作栏。
- 行级右键菜单与删除入口在 `ui/ProviderLayouts.swift` 的 `RowMenu`。

### 1.2 根因（四条，均为结构性）

| # | 问题 | 后果 |
|---|---|---|
| 1 | 只换排列，未换层级 | 仅列表排列不同，新增/编辑仍共用未重做的 `EditForm` |
| 2 | 440 窄旧表单不滚动 | 三段内容溢出即不可达，保存按钮被挤出视口 |
| 3 | 新建 / 编辑 / 导入无共同层级 | 前两者同面板、导入另一 sheet，用户无法建立"我在第几层"的心智 |
| 4 | 状态与动作真假不一致 | 无 `refreshUrl` 仍可设定时；`testQuery` 通用兜底；失败仍显示成功；删除可绕过确认 |

## 3. 共同信息架构

四个维度互不替代，不得合并成一个状态灯：

| 维度 | 用户问题 | 数据来源 |
|---|---|---|
| 账号身份 / 凭证来源 | 这是谁、凭证从哪来 | manifest `authMode` + 本机 CLI 路径 |
| 额度查询 | 还能用多少、何时重置 | `fetch.sh` 输出 → `UsageCache` |
| 模型调用 | 能不能真的发一次请求 | `testModel` / `testPrompt` |
| 每日自动触发 | 几点自动跑一次 | `scheduleTimes` + `refreshUrl` |

### 3.1 授权模式（拟实现）

- 面向用户只有两类：**API Key**、**授权登录**。授权登录当前只读本机 CLI 凭证，**不提供 App 内 OAuth 流程**，UI 不出假按钮。
- 拟在内置 manifest 显式声明 `authMode`：`glm` / `ollama` / `opencode-go` / `cline` = `apikey`；`gpt` = `local`。
- 字段为**可选**，不破坏旧插件：老第三方 manifest 缺该字段时沿用现有 `authStyle` 回退（`Models.swift:39`），UI 标"兼容推导"。
- **`queryAuth` 只描述传输/存储契约**（bearer/jwt/cookie/header，凭证放哪个字段），**不作为用户可选的授权方式**出现在表单里。

### 3.2 两个开关、两个状态

- **自动查询开关** = 后台轮询额度。关掉它**不影响**手动「查询一次」。
- **自动触发开关** = 按时发送一次模型请求。与自动查询互不代偿。
- **数据状态**：未查询 / 查询中 / 最新 / 过期 / 认证失败 / 查询失败 —— 描述"这份数字从哪来、新不新"。
- **额度状态**：已用百分比 / 已用完 —— 描述数字本身。
- **「未查询」不是「未启用」**，UI 与文案不得互相替代。

### 3.3 查询能力（拟实现的 manifest 字段）

- 新增可选字段 `supportsQuery: Bool?`，**默认 `true`**，保持旧插件行为不变。
- 未知的 OpenAI/Anthropic 兼容端点，导入时写 `false`；UI 显示「未接入额度查询」；引擎**不调用 fetch，也不写 error**。
- 是否可自动触发**只看 `refreshUrl`**，与 `supportsQuery` 无关。

## 4. 三套方案

差异是任务模型，不是配色。

### A — 额度工作台（主线程推荐；用户未明确选 A）

画布 `#F6F7F3`、内容面 `#FFFFFF`、文字 `#202C29`、次级 `#566760`、边 `#D8E0D9`、主色 `#28624F`。

- 左 **176px 任务侧栏**：额度总览 / 供应商账号 / 自动触发。
- 中央：账号额度横行（徽标 + 名称 + 凭证类型 + 各桶迷你条 + 重置 + 状态/数据态 + 行内管理入口）。
- 编辑：**替换同窗主区域**，宽完整，三段固定（身份凭证 / 额度查询 / 模型调用）+ 触发段，底部固定保存取消栏。
- 导入：同窗大面板，与编辑同层级。

### B — 运行台

画布 `#191F28`、面 `#242D39`、字 `#EEF2F8`、次 `#B2BDCC`、边 `#465466`、强调 `#91BFF8`。

- 顶层导航：额度 / 触发计划 / 账号。
- 中央：高密度额度表 + 右侧检查器。
- 编辑：**检查器扩展为宽面板**，不再压成 440 窄窗；**窄窗时主表折叠**，把宽度让给编辑（目标 ≥550px 或全宽）。
- 导入：任务队列形态，逐项结果可重试。

### C — 账号设置中心

画布 `#F4F6FA`、面 `#FFFFFF`、字 `#202A3C`、次 `#59657B`、边 `#D8DFEC`、强调 `#4659A6`。

- 左 **230px 账号源列表**；账号是导航，不是任务。
- 右侧详情即分段可编辑表单（连接 / 额度 / 自动触发），底部持久保存栏。
- **分段切换与账号切换都走同一脏态保护**。
- 导入：连续步骤 sheet。

三套均需明暗两态。暗色**不按"同色相降明度"推导**：每套定义独立的语义 token（画布/面/文字/次级/边/主色/状态四色），逐对实测对比度。主题切换不构成方案差异。

## 5. 共同交互规格

### 5.1 选择与进入编辑

| 操作 | 行为 |
|---|---|
| 单击 | 选中（仅高亮） |
| 显式「编辑」按钮 | 进入编辑 |
| 双击行 | 进入编辑；编辑态双击退出（有脏态先确认） |
| Esc | 取消编辑 / 关闭覆盖层 |
| Cmd+S | 保存（仅编辑态且草稿有效） |
| Cmd+N | 添加 |
| Cmd+F | 聚焦搜索 |

### 5.2 保存语义

- 保存**只提交草稿**，不发任何网络请求。
- 关闭编辑、切换账号、切换导航，`isDirty` 即弹「放弃更改？」（保存 / 放弃 / 继续编辑）。
- 身份凭证段与额度查询段分离：改 URL/模型不影响已保存密钥。

### 5.3 三个动作，后果写清

| 动作 | 实际发生什么 | 判定 | 文案 |
|---|---|---|---|
| 查询额度 | 走 **provider 执行路径**（`fetch.sh`），非任意 HTTP 请求 | 可解码 Cache **且** 无业务 error **且** 至少一个有效桶。**退出码 0 不充分**——错误 Cache 也能 exit 0 | 「仅读取额度，不调用模型」 |
| 测试调用 | 走 **`RefreshTrigger` 现有协议** POST（不是 provider fetch 脚本） | HTTP 状态 + 可识别业务错误分别报：成功 →「调用响应成功」；失败 →「调用失败」。**超时 →「结果未确认」，不自动重试** | 二次确认：「会消耗少量额度，不保证重置 5h 窗口」 |
| 保存定时 | **只写配置**，不发模型请求；错过的时刻**不补发** | 写入成功即完成 | 「保存后于下一个时间点生效」 |

- 任何文案**不得声称额度窗口已重置**。
- 无 `refreshUrl` 时文案为「**当前适配仅监控**」，**不**断言"供应商不提供该端点"。

### 5.4 凭证与隐私（拟实现）

| 供应商 | 凭证 | 用途 | 状态 |
|---|---|---|---|
| GLM / Ollama / OC-Go | 一个共用 API Key | 查询 + 调用 | 拟实现（现状见 §7） |
| Cline | 一个 `apiKey` | 仅查询 | 拟实现 |
| GPT | 无 Key，只读本机路径 | 只读 | 拟实现 |

- 已有"查询 key / 调用 key 分开且值不同"的配置，**必须原样保留**并提示"待确认"，**不静默合并**。
- 不强行全站统一到 `headers` 或 `refreshApiKey` 单一字段：优先让 provider 脚本向 `ConfigStore` 已存凭证契约兼容读写，特殊解析留在插件脚本内。
- 存储精确契约在实现前用测试锁定；本文**不声称已迁移**。
- 密钥默认掩码；明文不写日志、不进 stderr。来源路径只读；不复制、不导出 OAuth refresh_token。

### 5.5 窗口

单例、记忆位置、标题栏可拖。最小 **900×620**（须实际验证：native 窗口 minSize 与 content view 最小尺寸一致），建议初始 **1080×740**。表单区滚动，主操作栏固定。

### 6.1 范围

### 6.2 现有支持 vs 预期能力（分列，勿混）

| 源 | 已支持 | 预期（尚未实现，标拟实现） |

| 9router | 4 个内置模板 + OpenAI/Anthropic compatible 端点 | 同左，补齐能力标记 |

### 6.3 流程

入口可见（列表工具条 + 空态首按钮）→ **源选择** → **候选预览**（每项标：可导入 / 已存在 / 仅调用 / 不支持+原因）→ **逐项结果**（成功 / 部分失败可重试 / 失败原因）。

### 6.4 硬约束

| 约束 | 说明 |
|---|---|
| 能力不臆测 | 未知 OpenAI/Anthropic 兼容 ≠ one-api 余额；导入写 `supportsQuery=false`，**不生成额度脚本再叫它"仅调用"** |

| 扫描异步 | 有超时与错误态、可取消；真实源只读 |
| 敏感值 | 预览仅掩码 |
| 历史用量 | 三家都不导入 |

## 13. 推荐与取舍

**推荐 A（主线程推荐；用户未明确选择 A）**

- 与现有数据形状最近：`refreshUrl` + 定时时间点天然是"任务型"两栏，A 的侧栏三项可一一对应。
- 同窗替换编辑直接解决根因 2、3：宽度完整、三段固定、操作栏固定，不新增窗口层级。
- 导入与编辑同层级，用户无需理解多层 sheet。
- 代价：中央行信息密度低于 B，账号多时需滚动。

**B**：账号多（>10）且常驻大屏效率最高；但宽检查器与 900×620 冲突，必须靠"主表折叠 + 编辑让宽"解决，否则退回窄表单老问题。深色运行台与菜单栏常态浅色反差较大。

**C**：账号即导航，最贴"设置中心"心智，持久保存栏最稳；但"额度"降级为详情中的一个分段，与 App 主用途冲突。
