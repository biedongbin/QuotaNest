## 1. 范围、优先级与判断规则

- 目标是原生额度／余额查看，以及明确可控的手动和定时模型调用，服务于多供应商、多账号。
- 供应商／来源范围固定为五家订阅包、Claude 本机数据来源包和通用协议包，共七包；包名与路径见 README。
- 不因参考产品支持更多服务而扩大范围；不做代理网关、自动切外部 CLI 账号、历史 token／费用热力图。
- 整体信息架构采用一个主方向；方案 C 只借鉴合适的草稿细节，不长期保留三套并行管理方案。
- 优先级“必须”表示范围内公开交付能力必须满足；“证据条件”表示供应商能力须先经 S3 取证才能开放。
- 优先级决定实施与核实顺序，不按缺陷严重等级豁免已知错误；尚未完成能力须在范围清单明确不发布。
- 以下 FR 子号稳定；每项均须有正常、异常、恢复证据，具体点击链与证据归档见 06。
- 术语统一为“查询额度”和“发送测试调用”；打开页面、保存、切 tab、导入均不能隐式消费模型请求。

## 2. FR-01 账号创建、编辑、删除与多实例

优先级：必须；模板的实际能力为证据条件。账号标识契约见 05 第 3 节。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-01.1 | 首次空态提供“添加账号／从本机导入”；新增先选 provider 模板或通用协议，再进入同一个完整编辑器 |
| FR-01.2 | 每个账号有 App 内稳定 UUID，providerId 独立；显示名称可重复且保留用户命名，不由邮箱生成文件名 |
| FR-01.3 | 同供应商可有多账号，各自配置、凭证、任务、草稿与数据隔离；切账号后不出现旧账号读数 |
| FR-01.4 | 一账号一整体配置草稿，含名称、凭证变更意图、自动开关、间隔与计划；切 tab 不丢，保存原子提交配置；运行记录独立落盘，不进草稿、不算未保存修改 |
| FR-01.5 | 格式／结构等校验错误须提示所属 tab 并可跳转，不能部分保存；合法但不完整配置可保存并标未配置，对应自动任务保持 OFF 且显式说明，不阻断独立能力 |
| FR-01.6 | 删除确认后取消尚未发送任务，仅清 App 自有凭证／缓存，不动 CLI 来源；已发回包按 accountId＋revision 丢弃，不复活账号或污染其他账号 |

正常：同名账号可分别保存、查询和重开，保存结果与各自内容一致。
异常：跨 tab 校验错误、保存失败或切账号存在未保存修改时，不能静默丢失或部分写入。
恢复：保留草稿并能定位错误；取消及切换等离开操作遵循 FR-10.2 的同一保护规则。

## 3. FR-02 凭证配置与只读 CLI 来源

优先级：必须；浏览器授权登录为证据条件，不预设可行登录实现。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-02.1 | 用户区分 API Key 与授权登录／CLI 来源；cookie、header、bearer、JWT 不作为用户账号类型 |
| FR-02.2 | API Key 由 App 管理并遮罩；已有 key 时空输入框表示“保持原值”，明确提供替换与清除动作 |
| FR-02.3 | 清除 key 需确认并随配置保存，完成后标缺凭证，依赖该 key 的自动任务 OFF、取消未发送工作并提示；另一凭证的独立能力不联动，空框不删除、取消清除保留原值 |
| FR-02.4 | CLI 来源只读，每次执行读取最新值；App 不写回 CLI auth，也不擅自使用 refresh_token 刷新 |
| FR-02.5 | S3 证明确有可行 OAuth 浏览器流程后才出现“登录”；否则展示来源说明与本机登录引导，无假按钮 |
| FR-02.6 | 本地身份字段与调用凭证分别处理；查询和调用是否可共用凭证由 provider 明确声明 |
| FR-02.7 | 同账号 token 轮换可沿用身份已确认的旧快照并标“需用新凭证验证”；登录换账号必须停止展示旧账号值 |

正常：替换 key 或外部 CLI token 轮换后，下次执行使用新凭证，用户能看清来源及验证状态。
异常：缺失／无法读／失效提示恢复方法，阻断相关自动请求，不转为模型调用探测。
恢复：按来源更新 key 或在本机工具完成登录，再显式查询；身份变化时按新账号重新取得快照。

## 4. FR-03 官方额度／余额查询与标准展示

优先级：必须；接口字段、权益窗口和调用启动窗口机制为证据条件。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-03.1 | 查询优先官方汇总端点；保留来源及原始语义，无证据不从全量流水重建余额 |
| FR-03.2 | 默认展示“已用”，每条明确写“已用 xx%”；官方已用百分比可直接展示，不要求另造次数或分母 |
| FR-03.3 | 官方剩余百分比仅在明确定义为同一 100% 配额时可用 100 减换算；自行计算需真实分子／分母且口径一致 |
| FR-03.4 | 缺失／NaN／无穷为 unknown／invalid，不显示 0%；无次数不造“62/120 次”；保留原始合法值含超额＞100%，仅进度条长度可限 0—100，原值和超额说明不丢 |
| FR-03.5 | 展示实际支持的动态窗口列表，不硬塞空 5h／周／月；套餐、单位、周期、重置时间有依据才显示 |
| FR-03.6 | 剩余额度／余额有依据时另行标明；余额标币种，不跨供应商或币种合计，不把货币等同 token |
| FR-03.7 | 成功需 HTTP 与业务结构均匹配；任意 2xx 或空 data 不能作为成功，失败不推进最近成功时间 |
| FR-03.8 | 查询失败仍显示身份匹配正确旧值及旧时间；耗尽与连接故障分开；resetsAt 过期只标待更新，不清零／满额，不以到点证明重置，按正常调度查询 |

正常：服务原始值、窗口、套餐和时间可与展示逐项对照；进度、颜色及提醒阈值都表达“已用”。
异常：解析错误、空响应、登录失效或断网有独立结果；无成功快照为 unknown，不伪造 0%。
恢复：查询成功后更新快照和最近成功时间，跨界面保持相同事实；旧账号回包不覆盖新身份。

## 5. FR-04 可控手动模型调用

优先级：必须；可调用模型、协议与凭证条件为证据条件，额度能力不能替代调用证据。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-04.1 | “发送测试调用”是明确动作，执行前让用户确认消费含义与目标账号、协议、完整地址、模型和凭证来源 |
| FR-04.2 | 确认不强制每次重复弹窗，但当前目标与消费提示始终清楚；查询按钮不共用或隐式触发模型请求 |
| FR-04.3 | 默认提示词“只回复OK”、最大输出 16 为目标建议，provider 可更严格；不接受 16 时须 S3 声明兼容最小预算与理由，不用未知模型、目录首项或大额测试硬套 |
| FR-04.4 | 调用结果在独立区域展示，不覆盖额度查询结果；请求超时 20 秒，已发送 POST 不自动重试 |
| FR-04.5 | 已发送后网络超时等结果不明时，说明“结果不确定，可能已消费”，不宣称确定失败且无消费 |
| FR-04.6 | 配置预检或 GET 读取模型目录不称模型调用测试；成功返回 OK 不证明额度重置或用量窗口已启动 |
| FR-04.7 | 可显式选“用当前草稿发送测试调用”，清楚展示目标与消费、不隐式保存；普通保存独立且不开请求；测试未通过仍可保存合法配置，定时计划保持未启／缺配置不可启 |

正常：一次明确动作产生一次目标正确的调用，用户可见执行中及独立结果。
异常：配置不全阻断发送并定位字段；同账号已有调用时不产生重复请求；发出后取消不保证撤销消费。
恢复：结果不明先查看独立结果与官方数据；再次发送必须是新的明确动作，不由系统自动重试。

## 6. FR-05 自动额度查询

优先级：必须；更严格的 provider 间隔或预算需声明并论证，详见 05 第 5 节。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-05.1 | 默认间隔 300 秒，可改 60—3600 秒，provider 严格下限优先；新账号仅查询适配／凭证完整且保存页明确展示时默认 ON，否则待配置且 OFF |
| FR-05.2 | 开启／间隔变更后 due＝保存生效时刻＋新间隔，无关保存不重置；手动成功可设 due＝success＋interval；保存不开请求，关闭后手动查询仍可用 |
| FR-05.3 | 仅账号、已确认身份、凭证／来源版本与 queryConfigRevision 均匹配才合并；变更后旧 op superseded、迟到回包不提交，新手动为新 op；全局 3、每账号执行 1 |
| FR-05.4 | 总预算 20 秒含新版本等待旧 op 释放的时间，最多保留一个 latest-only 接替意图；超时未发须明确可重试；单 GET 8 秒，连接失败最多重试 1 次且在总预算内 |
| FR-05.5 | 401／403 不重试；429 有效 Retry-After 按其暂停，缺失／非法则下次不早于 max(正常间隔,60s)；只影响对应 provider／账号查询范围，不停其他家模型计划 |
| FR-05.6 | 缺凭证阻断自动请求并提示恢复；睡眠唤醒后每账号最多补一次到期查询，散开且受并发约束 |
| FR-05.7 | 查询开关不联动模型计划，失败不触发模型；换 key／身份／相关查询配置使旧 op superseded，尽力取消只读在途与未发送工作；保存只更新配置，不自动排查询 |
| FR-05.8 (v0.2) | 每账号三开关即时生效不进草稿：主开关「启用监控」off＝不查询不调度不出现在菜单栏/HUD（复用 disabledSlugs 存储）；「悬浮窗显示」off＝悬浮窗/菜单栏隐藏但查询照常（tokenhud.floatingHidden.slugs）；「同步 HUD」off＝即时从 envs.json/ACCOUNT_ENVS 摘除（tokenhud.hudHidden.slugs）；删除账号同步清三存储 |
| FR-05.9 (v0.2) | 自动查询间隔为每账号分钟级覆盖（1—1440，UserDefaults tokenhud.interval.\<slug\>），缺省用 provider manifest intervalSec；主开关开＋有间隔＝自动查，「自动查询 开/关」只读展示位移除；间隔变更即时生效（due 按新间隔重算） |

正常：保存后下一到期点查询，关闭后手动查询有效，多个账号不超过并发限制。
异常：超时、失效、限流与缺凭证有结果，失败保留身份匹配旧值，自动开关不伪装成功状态。
恢复：凭证恢复或限流等待结束后按规则继续；唤醒不连续补发所有错过的查询。

## 7. FR-06 定时模型调用

优先级：必须；所有声称“启动窗口”的供应商机制均须经 S3 证实。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-06.1 | 新账号和新导入的模型计划默认 OFF，无预填已启用计划；启用需一次清楚的目标与消费确认 |
| FR-06.2 | 每日时间按本机时区，以严格两位 HH:MM 输入并去重；增删、校验、保存和最近结果均可见 |
| FR-06.3 | 审计 ID 含账号＋planRevision＋本地日期／时刻，另以账号＋本地日期／时刻跨版本防重；planRevision 仅时间表／调用目标／启用授权变更，名称或查询间隔不改变；started／terminal 历史承继 |
| FR-06.4 | 睡眠／退出错过的模型调用不补发，记录 skipped 及原因；无权限／不可用同样记录，不静默遗漏 |
| FR-06.5 | DST 缺失时刻跳过，重复时刻只执行第一次；手动改时区／时钟造成同一任务再次到达时按任务身份去重 |
| FR-06.6 | 模型每账号 1、全局 2；任一并发位满时计划 skipped busy，不等待／排队，手动明确 busy、需用户再动作；查询可并行 |
| FR-06.7 | 启用／改计划仅执行 scheduledAt 严格晚于保存生效时刻的事件，已开始分钟不追赶；变更取消旧未发送事件，关闭不保证撤销已发消费 |
| FR-06.8 | 到期事件绑定账号／planRevision／targetFingerprint／本地日期时刻／scheduledAt，发前与已保存已授权目标复核，不符则 superseded 不发，旧事件不得改发新目标；已发结果归原 op，不覆盖新计划 |

正常：同账号同本地日期／时刻最多一次，跨版本／DST 历史承继，多个每日时刻可各执行；后台按已保存计划运行，运行记录独立落盘，不改未保存草稿。
异常：忙碌、缺权限、缺凭证、不可用、过期事件或错过时刻均说明原因；已发 POST 不自动重试，结果不确定不伪称未消费。
恢复：修正条件后等待严格未来时刻，不借改目标／启停重发当日同刻；手动测试是独立明确 op，不冒充补发，不承诺额度重置。

## 8. FR-07 三源导入

优先级：必须；来源字段映射与可调用能力仍需证据。逐账号写入顺序见 05 第 8 节。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-07.1 | 9router／cc-switch／cpamp 只读异步扫描，每源总预算 10 秒、可取消，界面有扫描状态 |
| FR-07.2 | 区分未安装、空、无法读、坏库、权限受阻、超时；凭证不全或不支持的源账号也列出原因 |
| FR-07.3 | 预览包含来源启用状态与重复状态；源启用且可导入项优先勾选，停用项默认不勾但可选 |
| FR-07.4 | 同源稳定记录 ID 用于再导去重，已导入默认 skip、不覆盖；同名不算重复，用户命名保留 |
| FR-07.5 | 跨源疑似同账号提示用户选择保留两条，默认不合并；名称、脱敏名和自动序号均不是主键 |
| FR-07.6 | 确认后逐账号事务写凭证、配置和必要插件产物，全成功才登记；失败清自身新产物，不动旧内容 |
| FR-07.7 | 部分失败保留逐行结果，成功项锁定；重试仅 failed 且未成功项，不重复成功账号 |
| FR-07.8 | 取消后已成功项保留并明确报告，不承诺“全取消＝零变更”；不反写来源，不自动启模型计划 |

正常：选择后得到可核对的逐行结果，同源再导不会重复，跨源条目保持独立。
异常：超时、坏库、缺凭证、写入失败及部分成功都可见，不能显示全成功或改动来源。
恢复：修复失败原因后仅重试失败项；保留成功项及已有账号，不因恢复重命名或合并账号。

## 9. FR-08 管理窗、菜单栏、悬浮窗与 HUD 一致

优先级：必须；统一点击路径见 06，不以参考图代替目标交互。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-08.1 | 主窗左导航为“额度总览／调用计划／设置”；总览按 provider 分组，账号使用统一全宽单列面板；按显示名／供应商搜索，组头、搜索和账号面板右边齐 |
| FR-08.2 | 单列账号面板展示账号、套餐、实际窗口、数据时间和查询结果；查询／配置／启停直接可见，菜单栏及悬浮窗共用显示偏好、HUD 独立显示偏好均明确可操作；更多仅放低频或删除，右键复用相同动作 |
| FR-08.3 | 点账号在同窗进入详情并可返回；账号标题仅一次，品牌／认证／状态各自只表达一个含义；额度／账号配置／自动任务真实切换并共享草稿，无真实额度不画三张假 5h／周／月卡，未查询和错误有下一步 |
| FR-08.4 | 保存栏固定且错误可达；其他 tab 错误可跳转；查询结果与模型调用结果分区，默认刷新不发送模型调用 |
| FR-08.5 | 菜单栏／悬浮窗／HUD 是同数据快览，身份、已用语义、旧值、耗尽与错误一致；不另算一套额度 |
| FR-08.6 | 系统字体、标准控件与窗控，正文最小 12；640／900／1200 点宽均无横向裁切、随机卡宽或空白孤岛，窄宽控件可换行且保存／错误可达；不得提高 minWidth 回避窄宽验收 |
| FR-08.7 | 单击／双击开关对称，右键含主操作、打开／关闭、供应商管理、退出；文案跟随状态，按钮操作不静默 |
| FR-08.8 (本轮) | 主窗左栏导航＋添加／导入；总览顶部搜索与筛选、供应商分组及全宽单列账号面板，统一内容宽度；停用状态可识别但控件文字清晰，禁用原因和操作反馈可见；多账号、长名称、无结果／空态自然可达 |
| FR-08.9 (v0.2) | 菜单栏下拉：顶部最近更新时间＋刷新余额；按供应商分组账号条目（每条多窗口迷你进度：标签+短条+%），点单条查询该账号；底部打开设置中心/悬浮窗开关/退出；宽约 320，停用与「悬浮窗显示」off 的账号不出现；额度页排查信息只保留「最近查询时间＋错误码（有错时）」内联结果条，其余诊断信息移除（后续需要再挪诊断页） |

正常：详情和各快览能对照同一账号与快照，tab 切换、搜索和返回都有可见结果。
异常：无结果、无快照、错误、禁用与执行中均有明确文案，不用占位 0 或假成功隐藏问题。
恢复：清搜索、修复配置或重查后，各界面自然更新，无需关闭重启才能同步。

## 10. FR-09 错误恢复、日志与诊断

优先级：必须；状态维度与诊断字段见 05 第 4、9 节。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-09.1 | 配置／凭证、查询操作、快照时效、额度值／耗尽、自动查询、模型计划独立表达；主行突出需行动问题，详情保留各维度 |
| FR-09.2 | 尝试有起止时间，快照有采集时间与最近成功时间；失败不推进成功时间，无成功快照为 unknown |
| FR-09.3 | 时效阈值默认为 2×查询间隔，provider 官方 TTL 可替代且最少 60 秒；错误与旧值能同时呈现 |
| FR-09.4 | 未配置＝缺必需配置，未接入＝App 无适配，不支持＝服务能力有证据不支持，待核实＝证据不足；不从缺 refreshUrl 推断不支持，不把权限／解析失败写成无额度 |
| FR-09.5 | 诊断能关联 accountId／opId，但不含 key、token、请求 headers 或完整返回；显示／导出各有脱敏 |
| FR-09.6 | 给出匹配错误的恢复入口；模型结果不确定、导入部分成功和验收未验证须明确，不能用统一成功提示覆盖 |

正常：用户能知道哪次操作、哪个账号、哪些值仍可信以及下一步如何恢复。
异常：断网、401／403、429、结构错误、缺来源或权限受阻各有原因和可见结果，不泄露秘密。
恢复：恢复动作保持账号和旧值关联，新的成功更新相应结果，不抹去尚未解决的其他维度问题。

## 11. FR-10 持久化、升级与窗口行为

优先级：必须；持久化方案为目标建议，实施前依 S5 兼容性审计决定。

| 子号 | 可观察行为与接受条件 |
| --- | --- |
| FR-10.1 | 保存仅整体原子提交配置，允许合法不完整并显式标未配置／对应任务 OFF；运行记录后台独立原子落盘，不等保存、不使草稿 dirty；保存不发调用或查询，重启保留配置及历史 |
| FR-10.2 | 取消无修改直接退出；有修改弹“放弃／继续编辑”；切账号、新增、导入、返回离开编辑及关窗采用同一草稿保护并恢复正确焦点 |
| FR-10.3 | 设置中心显示时使用 .regular，成为可由系统切换的常规 App 且主窗可 key；关闭后按统一策略返回菜单栏状态，X／Esc 和退出一致；单例前置、位置记忆、拖动缩放成立，浮窗保持 nonactivating 不抢焦点。Cmd-Tab 的 policy／key 证据与真实桌面按键证据分开 |
| FR-10.4 | 升级迁移不丢账号、不误清 key、不覆盖用户命名、不自动开启模型计划，失败有可恢复状态与明确结果 |
| FR-10.5 | 配置版本、App 凭证与 HUD／脚本兼容共同核对；最终安装包、实际运行版本与验收版本一致 |

正常：保存后重开内容一致，窗口位置与单例行为可复现；计划去重跨重启保持。
异常：写入／迁移失败或退出时有草稿均可见，不静默丢数据，不让按钮离开可视区。
恢复：继续编辑或确认放弃后完成原动作；恢复保存／迁移条件后重试，不产生隐式模型消费。

## 12. NFR 接受条件与 S2 出口

| 编号 | 接受条件与验证重点 |
| --- | --- |
| NFR-01 准确性 | 原始样本到已用显示可追溯，未知不为 0，单位／窗口真实，身份变化隔离，旧值与本次错误分开 |
| NFR-02 可靠性 | 预算、并发、取消、去重、唤醒／DST／重启和事务失败均有可重复的正常／异常／恢复样例 |
| NFR-03 隐私隔离 | 秘密不进普通诊断，来源只读，配置原子写；验证使用隔离 HOME，不污染真实配置 |
| NFR-04 交互一致 | 原生点击、Tab／焦点、草稿保护、右键、单例／位置、保存／错误可达及跨界面事实一致 |
| NFR-05 可复现交付 | 团队完成分层证据、独立 review 和安装包验证；权限受阻列未验，不把 QA 转交用户 |

S2 接受条件：FR 子项及其正常／异常／恢复均有对应技术规则与 06 验证路径，关键全局规则没有互相抵触。
验收同时核对以下交叉条件，不能把各单项通过简单拼成整体通过：

| 交叉条件 | 接受判定 |
| --- | --- |
| 保存与执行 | 合法不完整也可保存并提示对应任务 OFF；保存不查询／调用，草稿测试不保存，后台运行记录不写入草稿 |
| 身份与迟到结果 | 同账号轮换可标旧值待验证；换身份／删除后旧回包不得污染或复活账号 |
| 快照与本次错误 | 错误不改成功时间，不把正确旧值清零；重置时刻不证明服务已重置 |
| 计划与一次授权 | 新计划 OFF，目标清楚且配置完整才可启；已发请求不重试、不假称无消费 |
| 导入与恢复 | 同源成功项锁定、跨源不合并；取消／失败仅清自身新产物且报告已成功项 |

供应商文档已产出，逐家能力仍以来源、日期与样本证明；不得把本轮 UI 整改当接口机制取证。本轮按 [11](11-ux-remediation-acceptance.md) 核对新行为，不倒填历史审查结论。
最终公开交付能力不得有已知未解决缺陷；未完成能力在范围清单显式说明不发布，不能静默删承诺功能。
完成门槛还包括关键正常／异常／恢复实测、真实供应商数据对照、独立 review 和最终安装包一致，不以测试数或截图数代替。
