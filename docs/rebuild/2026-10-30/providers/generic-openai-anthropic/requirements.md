# generic-openai-anthropic 需求｜S3 供应商包 v0.1

日期：2026-10-30。证据分级：**B＝代码现状**（各内置 manifest 的调用声明归纳）＋协议公开常识引用。本包为**调用协议兼容包**：不是第三种授权方式，不承诺额度接口兼容（README 边界）。目标要求引用 [04](../../04-global-requirements.md)／[05](../../05-global-technical.md)。

## 1. 账号与授权

- 定位：用户自定义"通用协议账号"——任选 OpenAI 或 Anthropic 协议族、可编辑完整调用 endpoint（对比内置模板 URL 锁定，05 第 8 节：generic 可编辑完整调用 endpoint 与变体）。
- 凭证：API Key（bearer）；Anthropic 族另需 `anthropic-version` 头（B：内置模板用 `2023-06-01`）。
- 授权方式仍是 API Key 一种（FR-02.1）；本包不引入 cookie/OAuth 新类别。
- 多实例：不同 base URL／key／协议组合各自成账号；身份按 FR-01.2 UUID，同 URL 同 key 重复添加按同凭证提示但不强制阻止（用户命名自由）。

## 2. 额度语义

- **不承诺额度查询兼容**（README 边界）：OpenAI／Anthropic 官方及各兼容网关的余额／用量端点形态不一，本包默认"额度查询＝不支持"。
- 用户配了形似额度端点时也不自动当成功：须 provider 级字段映射证据，未取证前显示"本 App 未接入"（FR-09.4）。
- 例外路径：若某通用账号指向的服务恰好与已接入供应商同构（如 9router 网关转发 Claude），额度仍不合成——无官方汇总端点证据不从流水重建（FR-03.1）。

## 4. UI 要求（引 FR）

- FR-01.1：添加流程选"通用协议"→选协议族（OpenAI/Anthropic）→完整 endpoint＋key＋模型。
- FR-04.1：发送测试调用前确认协议族、完整地址、模型、凭证来源——本包 endpoint 全可编辑，确认展示尤其重要（防拼错地址消费到错误服务）。
- FR-04.3：默认提示词"只回复OK"、最大输出 16；模型名用户自填，无目录兜底（不用目录首项硬套）。
- FR-03／FR-05：额度区显示"本包不支持额度查询"；自动查询开关不出现或置灰带原因（FR-09.4）。
- FR-06：定时调用计划可用；启用走一次消费确认（FR-06.1）。
- FR-08.5：三界面调用结果一致投影；额度区一致显示不支持。

## 5. 错误恢复

| 错误 | 判定 | 恢复 |
| --- | --- | --- |
| 凭证失效 | HTTP 401／403 | 换 key；调用结果区明示 |
| 地址错误 | 404／DNS 失败／TLS | 明示网络/地址错误；用户改 endpoint 重试 |
| 协议错配（OpenAI 地址配 Anthropic 协议） | 4xx 或非预期结构 | 结果区展示响应摘要，提示检查协议族与 endpoint 匹配 |
| 结果不明 | POST 已发后超时 | 标"结果不确定，可能已消费"（FR-04.5），不自动重试 |

无额度旧值语义（无查询）；恢复均为配置修正后新的显式动作。
