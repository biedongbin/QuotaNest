## 1. 技术边界与最小实现方向

- 默认 SwiftUI＋AppKit 原生界面；菜单栏、悬浮窗、HUD 共享同一事实，界面投影不各自推算额度。
- provider 插件、manifest 和解析器承担供应商差异，主框架只执行已声明能力，不按 providerId 堆 switch。
- 范围仍为 README 的七包；不引入代理、切外部 CLI 账号或历史费用热图，不长期保留多套管理信息架构。
- 稳定身份、快照隔离、时间语义、两执行器及两调度是必要职责，不要求每项新建类、模块或服务层框架。
- 不预定数据库、代码生成器、新依赖或全量重写；S5 审计后才决定代码复用与磁盘协议迁移。
- provider 的字段、真实协议、OAuth 可行性和启动窗口机制须 S3 取证；不能以旧能力描述或 2xx 推断支持。

## 3. 账号、来源和凭证版本

- `accountId` 是 App 内稳定 UUID；`providerId` 独立，`displayName` 可重复，文件名不从邮箱／显示名生成。
- `origin(sourceName, stableSourceRecordId)` 只用于同源再导去重；跨源不擅自合并，显示名不是去重依据。
- `credentialRevision`、`sourceRevision` 是不含秘密的版本标记，不预定裸 token 哈希作账号主键。
- `accountRevision` 标记配置／身份关联版本；查询另以相关配置版本 `queryConfigRevision` 判断是否同 op，计划用独立 `planRevision`，不能由无关保存改调用任务身份。
- 同账号 token 轮换与账号／工作区身份变化分开处理：前者可保留有证据的旧快照并标新凭证待验证，后者不得展示旧身份值。
- 不能确认是否仍为同一账号／工作区时，不把旧值归到新身份；本地身份字段不能代替可发送的调用凭证。
- 执行开始固定 accountId 及相关版本；回包前核对账号仍存在、身份一致、相关版本仍适用，不让旧操作覆盖新状态。
- 查询与调用可否共用凭证、订阅适用范围及端点由 provider 明确声明，不能由字段碰巧存在来推断。
- App 管理 API Key；CLI 来源每次执行重新读取最新值，只读，不写 auth、不擅自刷新 refresh_token。
- 浏览器 OAuth 仅在 S3 有可行方案后提供登录动作，否则只给来源说明与本机登录引导。
- 删除顺序：确认→阻止新任务→取消尚未发送任务→撤销账号关联→清 App 自有凭证／缓存；不改 CLI 来源。
- 已发送请求不能保证取消消费；回包核对 accountId＋revision：已删除账号回包丢弃、不复活；版本过期禁止提交当前账号／快照／新计划状态，但已发模型调用因计划变更过期仍独立落原 op 历史，不覆盖新计划或其他账号。

## 4. 规范快照、状态和时间精度

| 对象／维度 | 目标规则 |
| --- | --- |
| 配置／凭证 | 已配置、缺失、不可读、失效或新凭证待验证；来源与账号身份分别记录 |
| 查询操作 | opId、账号／版本、手动或自动原因、start／end、结果及可恢复错误 |
| 快照 | accountId、已确认身份关联、来源版本、snapshotCapturedAt、lastSuccessAt、窗口列表及余额 |
| 快照时效 | fresh／stale／unknown；无成功快照为 unknown，错误是本次查询结果，不覆盖时效维度 |
| 额度窗口 | 原始 used／remaining／percent、单位、limit、period、resetsAt 及来源；字段未知不补 0 |
| 自动配置／运行记录 | autoQuery.enabled 与 modelPlan.enabled 是独立配置；started／completed／skipped／lastAttempt 等后台原子持久化，不入 draft、不等用户保存、不算 dirty |

内部时间表达带时区的绝对时刻并保留来源时区信息；每日计划另存本机本地日期与 HH:MM，不能混用两类时间。
JSON schema 明确时间格式与精度，解码不得静默截断；具体来源格式由 provider 映射，不直接当显示字符串比较。
金额保留币种和源精度，内部用十进制定点／Decimal 等无二进制浮点漂移的表示；序列化精度须有往返样例。
规范 schema 与 HUD／既有缓存 projection 分别版本化；S5 先评估现有消费者兼容，再决定适配或迁移，不直接改磁盘协议。

- 查询成功须 HTTP 状态与业务结构都匹配 provider 契约；任意 2xx、空 data、HTML 登录页不得写为额度成功。
- 操作开始／结束更新 attempt；仅业务成功推进 lastSuccessAt，快照采集时间与尝试时间不互相冒充。
- 过期阈值默认 2×已保存查询间隔；有官方 TTL 按声明使用，最少 60 秒；失败保留身份匹配正确旧值及旧时间。
- 官方已用按原义，剩余仅同一 100% 配额才做 100 减，自算需同口径真实分子／分母；保留合法超额＞100%，仅条长可限 0—100；缺失／NaN／无穷为 unknown／invalid，不补 0。
- 展示动态窗口，不制造空 5h／周／月或次数；金额不跨供应商／币种合计，额度耗尽不映射成连接失败。
- resetsAt 已过去只标待更新，不能把额度清零／满额，也不能把到点当重置证据；按正常查询调度取得新数据。
- “未配置”是缺少所需配置；“未接入”是 App 无适配；“不支持”须有服务能力证据；“待核实”是证据不足。
- 缺 refreshUrl、缺字段或本机不可读不能据此推断服务不支持；状态原因在详情保留，主行仅突出需行动问题。

## 5. 查询执行器与自动查询

查询事件顺序：用户动作／正常到期→固定身份及查询版本→匹配键合并或建立新 op→限预算等待／取得执行位→读最新凭证并复核版本→GET／业务解析→版本复核→提交；保存不触发查询。

| 规则 | 目标行为 |
| --- | --- |
| 间隔／新账号默认 | 300 秒，可设 60—3600 秒，provider 严格下限优先；查询适配／凭证完整且保存页明确可见才默认 ON，否则待配置且 OFF |
| due | 开启／间隔变更＝保存生效时刻＋新间隔，无关保存不重置；手动成功可将该账号 due 设为 success＋interval，保存不发请求 |
| 合并键 | 仅 accountId＋已确认身份关联＋credentialRevision／sourceRevision＋queryConfigRevision 全匹配才附着；重复点击共用 opId |
| 并发／接替 | 全局 3、每账号执行 1；版本变更的新 op 最多保留一个 latest-only 接替意图，旧执行位清理释放后才发，不能吞掉新动作 |
| 超时 | 总 20 秒含接替／并发等待，单 GET 8 秒；等旧查询超时未发明确“旧查询结束前未发送／超时，可重试”，不得伪成功 |
| 重试 | 连接失败最多重试 1 次，仅总预算内；401／403 不重试，其他错误不盲目循环 |
| 限流 | 429 有效 Retry-After 按其暂停；缺失／非法则从收到响应起至少 max(正常间隔,60s)；仅对应 provider／账号查询范围，不停其他家模型计划 |
| 缺凭证 | 缺配置保存为未配置，对应自动任务 OFF 并提示；执行时来源缺失也阻断请求，不用模型调用补探测 |
| 唤醒 | 每账号最多补 1 次到期查询，不逐次补发历史任务；受并发和暂停约束 |

更严格下限、不同预算或响应特别规则必须由 provider 声明并论证，不能为某供应商暗改全局语义。
Retry-After 格式按标准／provider 证据解释；缺失／非法使用上述兜底并显示依据，不把查询限流扩大成全局模型暂停。
换 key／身份／相关查询配置使旧 op superseded，取消未发送工作、尽力取消只读在途；迟到回包禁止提交，新动作不得附着旧 op。
新 op 接替／被较新意图替代／预算未发均须有独立结果；同版本附着共用 opId，失败不改成功时间、不清正确旧值；关闭仅取消未发送自动工作，手动仍可用。

## 6. 模型调用执行器与确认边界

调用事件顺序：手动明确目标／已启用计划生成绑定事件→校验配置与并发（忙则不等待）→读取最新凭证→发送前复核版本／授权目标与防重键→计划原子记 started→发送→独立持久化原 op 结果。

- 调用目标包含账号、协议族与变体、完整 endpoint、模型、凭证来源、提示词和最大输出；不从额度 URL 盲拼。
- 默认提示词“只回复OK”、输出 16 为建议，provider 可更严格；不接受 16 时须 S3 声明实际兼容最小预算及理由，不用未知模型／目录首项或大额测试硬套。
- 手动动作需清楚确认消费与目标，不强制每次重复 modal；可显式“用当前草稿发送测试调用”，按该草稿展示目标、不隐式保存；正常保存独立且不发请求。
- 计划启用需一次清楚确认；仅用已授权配置，消费目标变化不能沿旧授权。测试未通过不妨碍保存合法配置，但计划保持未启，缺配置不可启；不能让“保存并测试”成为唯一保存入口。
- 请求超时 20 秒，已发送 POST 一律不自动重试；网络超时／断连导致结果不明须标可能已消费。
- HTTP／业务结果匹配才标调用成功；额度快照不因调用成功而合成，也不直接宣布窗口重置或已启动。
- 配置预检或模型目录 GET 不是“模型调用测试”；查询与模型调用保留独立结果区和 opId。
- 模型并发每账号 1、全局 2，任一执行位满时计划 skipped busy、不等待／排队；手动明确 busy，须用户再次动作，查询可并行。
- 尚未发送可取消，已发送只能取消等待或展示状态，不能承诺撤销消费；再次发送必须有新明确动作。

## 7. 每日模型调度与持久去重

| 项目 | 规则及可验证结果 |
| --- | --- |
| 时间格式 | 本机时区每日严格两位 HH:MM，校验小时／分钟范围并去重，不悄悄修正为另一个时刻 |
| 计划版本 | planRevision 仅随时间表／调用目标／启用授权变更；名称、自动查询间隔等无关保存不递增，也不改调用任务身份 |
| 事件／审计身份 | 到期生成时绑定 accountId＋planRevision＋targetFingerprint＋本地 date／HH:MM＋scheduledAt；审计任务 ID 为账号＋计划版本＋本地日期／时刻，指纹不含秘密 |
| 跨版本防重 | 另持久键 accountId＋localDate＋HH:MM，日期按排程当时本机日历；已有 started／terminal 登记则不再发，新版本继承当日执行／skip 历史 |
| 执行前 | 核对事件仍等于已保存已授权版本／目标，不等则 superseded 不发，不拿旧事件读新目标；防重与 started 原子持久化后才发，落盘失败不发送 |
| 生效边界 | 仅 scheduledAt 严格晚于本次保存生效时刻，保存所在已开始分钟不追赶；变更取消旧未发送事件，已发结果保留原 op 历史、不覆盖新计划 |
| 重启去重 | started／完成／skipped 等已登记任务跨重启保留；无法确认结果不自动重发 |
| 睡眠／退出 | 错过的模型时刻记 skipped(reason)，不补发；恢复运行时补记录不等于补请求 |
| 不可用 | 无权限、凭证缺失、账号不可用、并发不可用等记明确 skipped 原因，不静默漏任务 |
| DST | 不存在时刻 skipped，重复仅第一次；首次登记后改别的时刻／再启停／改目标也不能重发同账号当日同刻 |
| 改时区／时钟 | 依排程时本机日历日期及跨版本防重键判重；每日多个时刻可各一次，不承诺所有时刻合起来一天只发一次 |
| 关闭计划 | 取消尚未发送工作，保留历史；已发送结果继续如实记录，不宣称能撤销消费 |

新账号／新导入计划 OFF，无预填已启计划；查询启用与调用计划启用是两次独立配置行为。
两执行器分别占并发位；同账号查询与模型请求可并行，但不得用查询错误触发模型发送。
started 后崩溃可能无法确定是否已发送：恢复标结果待核对／不确定，不能为得到“成功”自动重发。
草稿只提交计划配置／启停；started／completed／skipped／attempt 等由后台独立原子落盘，不写 draft、不改 dirty。未保存编辑期间只执行已保存且授权的版本，UI 明示该版本；手动测试是独立 op，不作计划补发。
窗口启动与额度重置的关联只按 S3 供应商机制证据说明，不纳入通用调度成功判据。

## 8. 草稿提交与三源导入事务

账号编辑：建立整体配置 draft→各 tab 改 section→区分格式合法性与执行完整性→原子提交配置→仅更新受影响版本／due 并取消旧未发送事件，不排新查询。

- draft 只含名称、凭证变更意图、自动开关、间隔与计划配置；运行记录独立，后台结果不丢草稿、不构成 dirty。
- 格式／结构错误跨 tab 提示并阻止提交；合法不完整可保存且标未配置，将对应自动任务 OFF 并显式提示，不调用模型或立即查询，不联动独立能力。
- key 空且已有值表示保持原值；替换／清除是独立意图，清除确认后随配置提交，禁用依赖该 key 的未发送任务，不影响另一凭证能力，不把空框／遮罩当 key。
- 取消、切账号、新增、导入、返回离开编辑及关窗走同一 guard：无修改直接离开，有修改放弃／继续编辑。
- 放弃后执行原离开动作；继续编辑保留当前 draft、tab 及焦点，错误跳转定位实际字段。
- 内置模板分别标额度查询地址／模型调用地址并只读；generic 可编辑完整调用 endpoint 与变体。

导入：异步只读扫描→预览／选择→逐账号事务→逐项结果；三源 adapter 不写源库或凭证。
每源总预算 10 秒且可取消，分别报告未安装／空／无法读／坏库／权限／超时；缺凭证或不支持也保留行及原因。
预览含 source enabled、重复及可导入性；启用可导项优先勾选，停用默认不勾可选择，不能默认勾不可导项。
同源 origin 已成功登记则默认 skip、不覆盖；相同名称不重复，跨源疑似身份默认不合并并提示保留两条。

1. 固定所选源记录与导入意图，分配新 accountId，检查同源成功记录，已有成功项锁定不重跑。
2. 逐账号准备凭证、版本化配置和必需插件产物，标明 App 所有权；不覆盖已有账号或既有产物。
3. 完成该账号全部落盘后才登记成功与 origin；中间失败清该事务自身新产物，不动来源和旧内容。
4. 展示逐行 success／failed／skipped 及原因；只重试 failed 且未成功项，同源成功登记再次检查。
5. 取消停止未完成工作；已成功项保留并报告，当前未成功事务清理自身新产物，不声称零变更。

导入计划默认 OFF；凭证展示／导出脱敏，原始来源身份与用户命名保持，不以遮罩名或序号代替标识。

## 9. 存储、迁移、诊断与 HUD 投影

建议最简方案为版本化 JSON 配置＋App 拥有的独立凭证文件，凭证权限 0600，以同目录临时文件和原子 rename 替换。
文件原子替换不等于多文件事务；导入按第 8 节提交／清理顺序，崩溃恢复须能识别自己的未完成新产物。
账号、自动开关和计划配置整体提交；读写故障、权限或迁移失败须保留可恢复版本，不提示全部成功。

| 方案 | 取舍与当前立场 |
| --- | --- |
| 版本化 JSON＋凭证文件 | 结构简单且便于 HUD／脚本读取，须验证 0600、原子替换、并发读及失败恢复；当前目标建议 |
| Keychain | 可减少明文秘密文件，但须核对 HUD／脚本访问、授权提示和迁移恢复；留 S5 评估，不先破坏兼容 |
| 数据库 | 多表事务可能有益，但当前规模与职责未证明需要，新增迁移和消费者兼容成本；不强推 |

- canonical 内部数据与 HUD／缓存 projection 各有 schemaVersion，投影只含消费者所需字段，时间／金额精度显式映射。
- 既有 HUD 文件路径与字段未知，S5 审计前不改磁盘协议；先取得兼容样本，再设计 adapter／迁移及回滚。
- 日志含 accountId、opId、类型、时间、耗时和安全错误原因；普通 diagnostic 不含 key／token／headers／完整返回。
- 不把凭证或邮箱拼成文件名／操作主键，导出遮罩与身份关联分开，不为排错持久化完整敏感响应。
- 迁移不得静默删账号、改名或自动启模型计划；清理仅 App 自有数据，不能触碰 CLI auth。
- 测试使用隔离 HOME／临时数据和脱敏 fixture；本轮不验证现有配置位置或外部工具数据。

## 10. 状态投影与原生 UI 验收能力前置

- 主窗为总览／调用计划／设置，同窗详情含额度／账号配置／自动任务，共享整体草稿；配置页同时提供查询与明确消费的草稿测试，自动任务页只管理每日计划、启停、下一执行和结果。
- 总览按 provider 分组，账号全宽单列，搜索／组头／面板使用同一内容边界；640／900／1200 宽依可用空间换行，不用提高 minWidth 掩盖裁切；快览投影同一事实。
- 默认“已用 xx%”，窗口动态列表，数据时间与查询结果可同时显示；调用结果独立，耗尽不画成连接故障。
- 常用查询／配置／启停与两个展示偏好直接可操作；更多／右键共享动作实现，禁用原因与独立结果可见；正文最小 12，保存和错误在全部验收宽度可达。
- 窗口单例、位置、X／Esc、拖动缩放、焦点／Tab、右键与开关文案是行为契约，不由静态截图推断。
- 设置中心显示前设 .regular 并使单例窗口可 key；关闭与退出统一收敛策略，浮窗仍 nonactivating。验证 activation policy／key 状态不冒称已在桌面按 Cmd-Tab。
- 能力不足或权限受阻逐项记未验；离屏选 tab、直接改状态或渲染图不能证明真实 tab 点击与保存通过。

## 11. 测试方法、证据与阶段出口

以下事件顺序是技术验收契约，当前轮只执行 [11](11-ux-remediation-acceptance.md) 范围；使用可控时间、临时 settings／HUD／日志、独立 defaults 及脱敏响应，不能仅 export HOME。

| 事件场景 | 前置状态 | 需要证明的顺序及结果 | 对应 |
| --- | --- | --- | --- |
| 保存／清 key | draft 合法但可不完整 | 原子提交配置→缺依赖任务 OFF 并提示，不联动独立凭证能力；无关保存不重置 due／planRevision，不发请求 | FR-01.4/5，FR-02.3 |
| 查询合并／换版本 | 旧查询未回时换 key 后手动点查 | 同键才附着；旧 op superseded／回包丢弃，新 op 最多 latest-only 等执行位，等待计总预算，并发每账号 1，未发明确可重试 | FR-05.3/4/7 |
| 查询总预算 | 首次 GET 连接失败 | 仅允许一次预算内重试，8 秒单次与 20 秒总预算均不突破 | FR-05.4/5 |
| 429 后自动到期 | Retry-After 有效／缺失／非法 | 按有效值或 max(interval,60s) 兜底，暂停仅对应查询范围，不停其他家模型计划；到期无风暴 | FR-05.5 |
| token 轮换 | 已确认同身份旧快照 | 新凭证版本→旧值标待验证→新请求；旧版本回包不能写成新凭证成功 | FR-02.7，FR-09.2 |
| 登录换身份 | 原账号请求未回 | 阻断旧展示→新身份关联→旧回包丢弃，新身份无快照为 unknown | FR-01.3，FR-02.7 |
| 删除中回包 | 请求已发送 | 停新任务／撤销关联→仅清 App 自有数据→回包丢弃，不复活账号 | FR-01.6 |
| resetsAt 到点 | 有合法旧快照 | 保留数值→标待更新→正常查询，新响应前不合成零用量或满额 | FR-03.8 |
| 草稿测试失败 | 草稿合法、计划未启 | 显式确认草稿目标→请求／结果独立→不保存；之后可普通保存，计划不启 | FR-04.7 |
| 模型发送后断连 | POST 已发 | 记录结果不确定／可能消费→不自动重试，用户再次发起才是新操作 | FR-04.5，FR-06.8 |
| 计划发送后崩溃 | started 已持久化 | 重启读取任务身份→不重发→保留待核对结果，不能伪造成功 | FR-06.3/8 |
| 调用位占满 | 同账号 1 位或全局 2 位占用 | 计划 skipped busy、不等不排，手动提示 busy 需再动作；释放不补该任务 | FR-06.6 |
| DST／跨版本防重 | 首次重复时刻已登记后改时间／启停／目标 | 继承同日同刻 started／terminal 历史，第二次重复时刻不发；名称／查询间隔不变 planRevision | FR-06.3/5 |
| 草稿与后台 | 未保存修改时已保存计划到期 | 按已保存授权目标执行，started／结果独立落盘，不改草稿与 dirty，不等用户保存 | FR-01.4，FR-10.1 |
| 旧事件变更目标 | 到期生成后发送前保存新计划 | 取消旧未发送事件→发前版本／targetFingerprint 复核，不符 superseded 不发，已发结果只归原 op | FR-06.7/8 |
| 唤醒两类到期 | 查询／调用均错过 | 查询每账号最多补一次并限流；模型只补 skipped 记录，不补请求 | FR-05.6，FR-06.4 |
| 导入某步失败 | 当前账号产物未全成功 | 清本事务新产物→不登记成功→保留旧内容，重试仅未成功项 | FR-07.6/7 |
| 导入后取消 | 前几账号已成功 | 停止未完成→清未成功新产物→保留成功登记，报告实际变更 | FR-07.8 |
| HUD 兼容投影 | 规范数据带版本／精度 | 按版本投影→消费者样本比对→时间／金额往返一致，未经审计不改现协议 | FR-10.5，NFR-01 |

这些顺序同时对照 06 的真实操作链；内部事件证据只能证明执行规则，不能替代点击与保存路径。
验证报告逐项写通过／失败／未验及原因；权限不足或缺样本不升级成通过。
字段和 capability 的 provider 例外须保留论证，不能靠隐藏开关绕过已定预算或消费确认。
迁移与接口兼容结论留给对应阶段，以目标 JSON 方案存在为由直接覆盖当前协议不符合本规范。
