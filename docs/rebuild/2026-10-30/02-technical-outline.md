## 1. 设计前提与待定边界

- 默认继续使用 SwiftUI＋AppKit 表达原生管理窗、菜单栏和悬浮窗；这不是对现有代码可复用性的判断。
- 保留插件式供应商：新增供应商通过 provider 插件、manifest 与解析器接入，主框架不增加供应商 switch。
- 需求从零重建不等于代码必须重写；S5 才决定复用、修复或重写。
- 模块具体名称和接口形状仍按证据设计；S2 建议版本化 JSON＋App 自有凭证文件，Keychain／既有 HUD 兼容取舍留 S5 评估，本大纲不宣布迁移已采纳。
- 账号快照隔离、时间语义和两类独立调度是必要要求；不预先要求数据库、服务层框架、代码生成器或全量重写，也不预设大量抽象与新依赖。
- 方案 C 与 AIUsage 只提供候选和学习材料，不能代替需求、原生交互验证或架构决策。
- FR-01—FR-10、NFR-01—NFR-05 与需求大纲共用稳定编号；具体请求字段和协议变体不在缺证据时定死。

## 3. provider 与调用协议边界

- manifest 声明能力和配置边界，provider 解析服务特有响应；主框架只编排通用流程，不按 slug 判断服务语义。
- 每项能力区分“本 App 未接入”“服务不支持”“尚未核实”；账号“没配置”属于另一维度。
- 查询能力、模型调用能力、凭证要求和订阅适用范围分别说明，不能从某一能力推断另一能力。
- 用户授权主要是 API Key／授权登录，CLI 是凭证来源；cookie、header、bearer、JWT 是技术传递方式。
- OpenAI／Anthropic 是调用协议族，OpenAI 的 chat-completions／responses 等变体须按证据分别处理。
- 不把所有地址拼成 `/v1/messages`，不从调用兼容性推断额度接口兼容性，也不盲目共用查询与调用地址或凭证。
- 优先官方额度／余额汇总端点；无证据不用全量流水推导余额；特殊解析留在 provider 内。
- 订阅、窗口、单位、重置时间等字段由逐家证据决定，缺失字段保留未知，不为统一展示造数。
- provider 文档包给出默认安全值和允许编辑范围；本大纲不凭旧配置推断账号、协议或模型已支持。

## 4. 账号、凭证与持久化

- 账号实例具有稳定身份，支持同供应商多实例；显示名称允许重复，用户命名须保留。
- 来源稳定标识、账号身份、显示名称、凭证来源分别管理；脱敏名或自动序号不能充当主键。
- S1 的 `sourceFingerprint` 是来源关联概念；S2 细化为稳定 accountId、credentialRevision／sourceRevision 与身份关联，均不含秘密，不预定裸 token 哈希主键。
- 换 key、换来源、切账号与删除账号时，配置、执行中请求、任务和缓存的关联及清理规则须一起定义。
- 旧请求回包必须确认仍属于当前账号及来源，不能覆盖新凭证下的数据或写入另一个账号。
- CLI 与导入源只读，不修改外部工具的凭证、活动账号或配置；失效／缺失要可诊断。
- 秘密仅在必要边界传递；表单遮罩、导出脱敏、日志过滤分别验证，不能靠改写真实身份实现脱敏。
- 配置保存须原子写入并给出成功／失败结果；迁移不能静默丢账号、改用户命名或开启模型调用。
- 存储方案及迁移失败恢复在 S2 设计；本文不宣布采用 Keychain，也不把当前文件布局认作目标。
- 验证使用隔离配置与测试 HOME，不读取或污染真实 HOME；构造样本不含真实凭证。

## 5. 查询执行器、快照与缓存

- 查询执行器只负责已声明的额度／余额读取，不在失败时用模型调用兜底“验证”。
- 查询与模型调用使用独立操作结果，结果含所属账号、来源、发起原因、时间及成功／失败／取消信息。
- `lastAttemptAt` 记录尝试，`lastSuccessAt` 记录成功，`snapshotCapturedAt` 记录快照采集，三者不可互相冒充。
- 规范快照与回包按账号、已确认身份及来源／凭证版本复核；S2 允许同身份 token 轮换保留旧值并标待验证，身份变化不能显示旧账号值，旧回包不得覆盖新状态。
- 每个窗口保留原始 `used / remaining`、单位、`limit`、`period`、`resetsAt` 与对应语义，未知项不补 0。
- 服务直接提供 `percentUsed / remainingPercent` 时按原义使用，无需另造分母；自行计算时须有真实分子／分母且口径可比，不推造次数总量，不跨供应商合计，不把货币等同 token。
- `fresh / stale / unknown` 表示快照时效，查询结果表示本次操作；二者与凭证状态、额度耗尽、两个自动开关分别表达。
- 查询失败须保留身份匹配且有依据的正确旧快照，显示其旧值与时间；失败尝试不能刷新成功时间或把旧数据画成最新。
- 所有请求有超时、受控重试与总请求预算；并发、去重、取消和旧回包处理在 S2 细化，不设无界重试。
- 官方数据与本机统计保留来源区别，接口返回与标准展示之间的映射用脱敏样本对照。

## 6. 模型调用与两个独立调度任务

- 模型调用执行器仅接收显式手动动作或已启用的调用计划；保存、开页面、切 tab、导入均不隐式消费。
- 调用配置必须确认协议／变体、地址、模型、凭证与消费含义，不能以“刷新”一词隐藏模型请求。
- 新调用计划默认关闭；导入及升级迁移均不得自动开启。启用校验失败须可见并保持可控状态。
- 自动查询与定时调用分别有开关、配置、执行状态和最近结果；禁用一类不阻止另一类的合法动作。
- 自动查询关闭时手动查询仍可执行；手动模型调用始终需要明确动作。
- 调用成功只能证明该请求的结果；窗口启动／额度重置／官方周期变化须另有机制及数据证据。
- 两类调度以本机时区表达；时间配置的增删、校验、保存和反馈在 S2 写清。
- S2 已定义错过任务、睡眠唤醒、跨天、DST、重启、重复分钟和互斥策略，详见 05 第 5—7 节。
- 编写 S1 时补发政策待定；现按 S2 执行模型错过不补、查询唤醒最多补一次等规则，不以历史待定表述覆盖。
- 并发与重复点击、取消／超时后的重试须避免静默重复消费；已发送请求的结果不明不能假称未消费。
- 调度测试采用可控时间和隔离配置；不能为了验证分钟触发而无计划地重复真实模型调用。

## 7. UI 状态、草稿与跨界面投影

- 管理窗、菜单栏、悬浮窗、Claude Code HUD 使用统一账号／快照／操作状态；投影只改变信息密度，不改变事实。
- S2 已统一默认展示“已用 xx%”，各投影始终标注；进度、颜色和提醒阈值与已用语义一致，不能把参考图的剩余绿色条直接套作已用绿色条。
- 未保存草稿与已保存配置分开，按账号和配置区隔离；切 tab 保留、保存／取消及重开规则在 S2 明确。
- 页面生命周期不触发模型调用；每个按钮有可见成功／错误／状态变化，禁用原因可理解。
- 焦点与 Tab 顺序、上下文菜单、提示文案及执行中交互覆盖正常与错误路径，不能只做静态布局。
- 窗口可关闭（X 或 Esc）、可拖动、全局单例且重复打开仅前置，记住位置；缩放后操作仍可达。
- 单击／双击开关语义对称；右键提供主操作、打开／关闭切换、供应商管理、退出。
- 文案随真实打开／关闭、执行中及错误状态变化；悬浮窗与菜单栏行为须以原生操作核实。
- 详细 UI 路径沿用需求大纲第 7 节，从空态到完成任务逐步展开，原型用于讨论而非通过凭据。

## 8. 三源导入、去重与恢复

- 9router、cc-switch、cpamp 分别通过 adapter 读取；扫描与预览只读，缺源／坏库／超时／取消均有结果。
- 预览展示可导入性、重复、停用与不支持的原因，凭证遮罩不影响真实身份匹配。
- 去重依据来源稳定标识和账号身份，不能依据显示名称、脱敏名称或自动序号；相同名称可以是不同账号。
- 保留用户命名；脱敏是展示与导出策略，不能篡改真实账号标识或使重试生成新身份。
- 来源内部稳定标识与跨来源同账号的判定、冲突选择及指纹规则须在 S2 定义，不能缺证据自动合并。
- 扫描→预览→确认→写入的边界、批量或逐项事务与回滚策略须明确，本大纲不先选定实现。
- 操作结果逐项记录成功／失败／取消及原因；部分失败重试只处理未成功项，不能重复导入成功账号。
- 中断恢复、源变动和配置写入失败不得静默丢数据或反写来源；计划导入后不自动开启消费。

## 9. 配置迁移、错误与诊断

- 保存与迁移采用原子写入；定义失败后保留可恢复状态，不把部分写入显示为全部成功。
- 配置版本及迁移规则在 S2 写明，跨重启账号／设置／上下文恢复按需求验收；消费计划不自动开启。
- 区分凭证失效、额度耗尽、网络错误、解析错误和未核实能力，提供与实际原因匹配的恢复入口。
- 查询与调用分别限制请求时间、重试与总预算；日志仅保留诊断必要信息，不记录秘密或未脱敏请求内容。
- 脱敏导出、错误消息与缓存身份共同检查，不能让排错渠道泄露凭证或错误账号的数据。
- 错误可见且可复现，保留正确账号的旧值；权限受阻、缺接口样本或无法操作均记录“未验证”。

## 10. 验证能力前置与交付证据

- S2 技术方案中前置检查真实 UI 验收所需的工具能力与权限、可点击路径及证据取得方式，避免交付末才发现无法验收。
- 本轮只写上述目标要求，不检查当前程序、运行状态、工具或系统权限。
- 验收方案须能真实打开窗口、点击 tab、编辑、保存／取消、关闭与重开，并核对各投影；受阻步骤逐项列未验。
- 离屏强制 tab、直接改内部状态、渲染图或旧截图不能证明 tab 点击、保存和恢复流程通过。
- 证据分层：契约／解析测试证明数据处理；接口样本证明字段；原生交互证明操作路径；安装包证明最终交付版本。
- 截图是状态记录，原型是设计材料，单测通过不能替代真实供应商对照、原生交互或安装部署证据。
- 验证在隔离配置下覆盖账号切换、换 key、超时／取消／旧回包、两类调度和导入部分失败等关键边界。
- 逐家样本证明原始数据与标准展示一致；真实验证调用须受控，不为取证开启大量模型消费。
- S6 需要实施者之外的独立代码 review；本轮不另启 agent，不提前进行代码审查。
- 构建、测试及打包必须使用项目规定的 swiftly 工具链；这里只保留交付约束，当前不执行命令。
- 最终核对构建版本、签名／打包状态、安装路径、实际启动版本与验收版本一致，不能只验证开发产物。
- 不堆任意覆盖率指标，不把权限拒绝或无法点击当作通过，也不把验收责任转给用户。
