## 1. 产品目标与范围

- 提供 macOS 原生的多供应商、多账号额度／余额查看，以及明确可控的手动与定时模型调用。
- 对确有动态额度窗口机制的账号，帮助用户在合适时间开始用量窗口；机制必须有证据，不能凭经验推广到所有供应商。
- “开始用量窗口”“额度重置”“官方固定周期”分别定义；一次调用不保证启动或重置窗口。
- 菜单栏、设置管理、悬浮窗、Claude Code HUD 展示同一账号的统一数据与状态。
- 本产品不是代理网关、模型路由器或账号切换器，不通过导入或管理账号去改写其他工具的活动账号。
- 团队负责用户自然操作路径和全面验收，不能要求用户逐项报 Bug 才补需求。
- “从零”是重建需求和技术定义；S1—S4 前置完备后，S5 才评估现有代码并决定复用、修复或重写。
- 既有方案 C 是候选，AIUsage 是学习材料；借鉴方向为按供应商分组、多账号并列、窗口／套餐／更新时间集中呈现、菜单栏展示同数据简版，最终视觉与交互在 S2 细化，不复制代理网关、切 CLI 账号或统计热力图范围。
- 保留插件式供应商约束：新增供应商经 provider 插件、manifest 与解析器接入，主框架不堆供应商 switch。

## 2. 领域与术语

| 对象 | 目标含义与边界 |
| --- | --- |
| 供应商服务／查询适配器 | 服务及其额度、余额数据读取与解释方式；额度能力与模型调用能力分别声明 |
| 账号实例 | 用户管理的独立账号条目；同一供应商可有多实例，显示名称不是身份主键 |
| 凭证来源 | API Key、授权登录所需凭证及只读 CLI 来源；来源变化不能沿用错误账号的数据 |
| 订阅权益／额度窗口 | 原始权益、余额、用量及周期语义；同一账号可能有多个窗口，不任意合并 |
| 模型调用配置 | 协议族及变体、地址、模型、凭证与提示词等调用条件；不从额度查询配置盲目推导 |
| 自动额度查询任务 | 独立控制查询启停、时间与结果；关闭后仍能手动查询 |
| 定时模型调用任务 | 独立控制可能消费额度的模型请求；新计划默认关闭 |
| 统一快照 | 与账号及来源绑定的标准化读数，同时保留服务原始字段语义和采集时间 |
| 操作结果 | 一次查询、调用、导入或保存的可见结果；成功、失败、取消与未验证不得混淆 |

用户层授权主要按 API Key／授权登录理解，CLI 是凭证来源；cookie、header、bearer、JWT 是技术传递细节。
OpenAI／Anthropic 是调用协议族；OpenAI 还包括 chat-completions、responses 等变体，不能硬拼 `/v1/messages`。
有 API Key 不等于能查余额，有额度 API 不等于支持当前调用路径；调用兼容也不证明额度接口兼容。

## 5. 调用与调度的共同约束

- 自动额度查询与定时模型调用是两个完全独立的任务、开关、配置与操作结果，不能共用一个含糊的“刷新”。
- 编辑、保存、打开页面、切 tab、导入不会隐式触发消费型模型请求；手动调用必须来自显式用户动作。
- 新增调用计划默认关闭；导入或升级迁移不得自动开启模型调用。
- 开启调用计划前，用户必须看见消费说明并确认协议／地址／模型／凭证；不能只靠开关名称暗示安全。
- 手动查询不依赖自动查询开关；查询失败也不能自动退化为模型调用来“验证”。
- 调用结果只能说明实际请求结果；不能把成功返回文字当作额度重置或窗口已启动的证明。
- 调度使用本机时区；错过任务、睡眠、跨天、DST、重启、重复分钟、并发互斥在 S2 详细定义。
- 编写 S1 时上述政策待定；S2 已明确模型错过不补发、查询唤醒最多补一次等规则，详见 05，不以本大纲的历史待定状态覆盖。
- 增删时间、启停、执行中及最近结果均有可见反馈；取消、超时或重试不造成静默重复消费。

## 6. 数据展示与状态契约

- 区分 `lastAttemptAt`、`lastSuccessAt`、`snapshotCapturedAt`；失败尝试不能更新为“最近成功”。
- 快照绑定稳定账号、已确认身份及来源／凭证版本；S2 细化为轮换凭证可保留同身份旧值并标待验证，身份变化不显示旧账号值，旧回包必须阻断，详见 05。
- `fresh / stale / unknown` 表示快照时效，与本次查询结果、凭证状态、额度耗尽、自动开关独立；一次失败不能丢弃身份匹配且有依据的正确旧值。
- “没配置”“本 App 未接入”“服务不支持”“尚未核实”严格区分，并分别给出可理解的提示。
- 每个窗口保留服务原始 `used / remaining`、单位、`limit`、`period`、`resetsAt` 语义；未提供字段保持未知。
- 服务直接给出 `percentUsed / remainingPercent` 时按原义使用，无需另造分母；自行计算百分比时须有真实分子／分母且口径可比，不凭剩余额度猜总量，不把未知画成空额度。
- S2 已统一默认展示“已用 xx%”；剩余百分比换算条件见 04。进度、颜色、提醒阈值须与已用语义一致，不能把 AIUsage 的剩余绿色条直接复制成已用绿色条。
- 不跨供应商合计不同计量，不假定美元等同 token，不把本机统计冒充官方余额。
- 查询优先使用供应商官方汇总端点；无证据时不能用全量流水重建余额并宣称准确。
- 查询错误可见并保留身份匹配的旧值，明确其时间和过期状态；重试与总请求预算均有限制。

## 7. UI 全流程覆盖表

以下是 S2 详细路径的必填清单，不是当前 App 的测试结论；原生交互证据须由 S6 实际产生。
每行都要补正常、异常、取消及恢复结果，不能只展示一个成功截图。

| 路径 | 用户自然操作链 | 需要观察的结果／边界 | 关联 |
| --- | --- | --- | --- |
| 首次启动 | 无账号→选模板或导入→配置凭证→手动查询 | 空态能前进，保存有反馈，查询成功可读；失败有原因与恢复入口 | FR-01/02/03/07/09 |
| 已有账号编辑 | 选账号→编辑→切 tab→返回→保存或取消→重开 | 未保存草稿按所属账号和配置区保留；保存生效，取消不误写；草稿处置细则在 S2 明确 | FR-01/08/10 |
| 键盘与焦点 | 打开配置→Tab 遍历→修改→执行操作→Esc | 焦点不丢失或跳到错误字段，键盘操作有结果，Esc 与关闭规则明确 | FR-08/10，NFR-04 |
| 多账号／CLI | 切账号→查看来源→尝试编辑→恢复缺失来源 | 各账号凭证／草稿／快照隔离；只读原因可见，不反写 CLI 配置 | FR-01/02/09 |
| 手动查询 | 关闭自动查询→点查询→等待→成功或恢复 | 手动查询仍可执行，耗尽／无数据／网络错误不混淆，不隐式调用模型 | FR-03/05/09 |
| 手动模型调用 | 确认调用条件与消费→显式调用→查看结果 | 发给正确账号与路径，执行中防重复，失败不会宣称窗口已重置 | FR-04/09 |
| 两类定时任务 | 分别启停→增删时间→保存→查看执行结果 | 开关互不联动；新调用计划关闭；边界事件按 S2 明确策略执行 | FR-05/06/10 |
| 导入扫描 | 选择三源之一→扫描→预览→取消或继续 | 缺源、超时、坏库有可见结果，取消可退出，来源保持只读 | FR-07/09 |
| 导入选择 | 查看重复／停用／不支持项→选择→确认 | 每项可导入性及原因明确；不把展示名、脱敏名或自动序号当身份 | FR-01/07 |
| 导入恢复 | 导入→部分失败→看逐项结果→重试失败项 | 成功项不重复，用户命名保留；中断、冲突及回滚结果须明确 | FR-07/09/10 |
| 数据退化与恢复 | 旧值→过期／登录失效／额度耗尽／断网→恢复查询 | 旧值、查询错误、凭证、耗尽与开关独立表达，恢复后各界面一致 | FR-02/03/08/09 |
| 主窗口生命周期 | 打开→重复打开→缩放／拖动→关闭→重开 | 全局单例且前置，位置记忆，可关闭；缩放后内容和操作仍可达 | FR-08/10 |
| 菜单栏／悬浮窗 | 单击／双击开关→右键→执行主操作 | 能用同一手势关闭，文案随状态变化；右键含主操作、打开／关闭、管理、退出 | FR-08/10 |
| 跨界面一致 | 在管理窗改账号或查数据→检查菜单栏／悬浮／HUD | 同一身份、同一快照和相同状态语义；不同信息密度不改变事实 | FR-03/08 |
| 重启与升级 | 保存→退出／重启或升级→重新查看 | 账号、设置、选中上下文及窗口规则按详细规范恢复，消费计划不被自动开启 | FR-06/10 |

所有按钮点击后必须有成功、错误或状态变化；不能静默，禁用项也须给出可理解的原因。
只读与脱敏是操作／呈现边界：名称可重复，脱敏不能篡改真实账号身份，查重依据来源稳定标识和账号身份。
旧截图不能证明新行为，原型不能代替原生点击；离屏强制 tab 或渲染图也不能证明 tab 点击、保存流程通过。
真实 UI 验收能力与权限须在技术方案中前置检查；受阻操作明确记“未验证”，不能以截图补成“通过”。

## 8. 逐家独立文档包

计划路径统一位于 `providers/<包名>/requirements.md` 与 `technical.md`，仅在 S3 按顺序产出。
包名固定为 `cline-pass`、`glm`、`gpt-codex`、`ollama`、`opencode-go`、`claude-code`、`generic-openai-anthropic`。
`claude-code` 单列本机／HUD 数据来源；兼容协议包不是第三种授权方式，也不提供未经证明的通用额度接口。
每包使用以下共同模板，未知项明确保留“待核实”，不先把请求字段或协议变体定死。

| 模板项 | 必填内容 |
| --- | --- |
| 账号与授权 | 账号类型、凭证来源、用户可编辑范围、只读来源边界及多实例身份 |
| 额度语义 | 官方权益／余额／用量、窗口起止、重置机制、单位、缺失字段及可展示值 |
| 查询字段与证据 | 真实请求／响应字段、权威引用、采集日期、脱敏样本及适用账号范围 |
| 调用能力与默认安全值 | 协议族／变体、地址／模型／凭证条件、消费说明；新调用计划默认关闭 |
| 定时语义 | 两类任务支持情况及窗口关联，引用 S2 边界政策并说明供应商例外证据 |
| 能力与错误 | 未配置／未接入／不支持／未核实的区别，错误分类与恢复路径 |
| 验收与未决项 | 正常／异常／恢复样例、数据对照、事实待验证清单和阻断影响 |

Cline 官方 usage-limits 在本会话已有实测描述，状态仍为“会话证据待转录／脱敏 fixture”，本轮不重访接口。
其他旧“能力”叙述不默认为事实；不为查证开启大量真实模型调用，模型调用成功也不能代替额度机制证据。
