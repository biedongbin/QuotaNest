# TokenHUD：供应商账号管理重构

本轮目标依据用户 2026-10-31 的直接说明制定。旧设计文档记录历史，不作为本轮需求来源。改造前代码基线为 `ec1f44e`。

## 核心目的

管理多个供应商的多个订阅账号。供应商类型提供固定协议、调用地址与可选额度解析器；账号实例独立保存名称、凭证、计划、缓存和展示偏好。

1. 每个账号配置 API Base URL、API Key、协议、测试模型，以同一条调用链进行连通测试和定时发送请求。
2. 发送 API 请求用于尝试触发供应商的 5 小时计费窗口。HTTP 成功不能直接证明额度已经重置，也不能由客户端强制供应商重置。
3. 额度查询是独立可选能力。可查询 5 小时、周、月以及供应商实际提供的其他窗口；百分比和下一重置时间可以分别缺失。没有数据不能显示为 0%，没有重置时间不能推算为调用时间加 5 小时。
4. 自定义供应商可仅管理 API 连接，也可配置精确额度查询 URL 和独立 API Key；不猜测供应商提供 billing 路由。标准 JSON 适配格式为 `windows` 数组或 `five_hour` / `seven_day` / `monthly`，可包在 `data` 中。
5. GLM、OpenCode Go、Ollama 等内置供应商是可复用类型，绑定独立脚本。API Key 与网页 Access Token / Cookie 分开保存。尚无代码或离线样本证明的页面结构不能声称已经支持。
6. 新增时选择类型；复制账号复制地址、协议、模型和时间点，生成独立实例，清空全部凭证及结果，定时调用默认关闭。
7. 账号可分别控制菜单栏/悬浮窗显示、Claude HUD 输出。HUD 以稳定账号标识投影缓存，支持同类多个账号，保留外部条目。

## 架构改造

保留插件扫描和 manifest 驱动的扩展边界，避免将任何供应商 slug 条件放入通用配置和调用框架。

- 类型定义：bundle 的 `providers/<type>/manifest.json` 与 `fetch.sh`。
- 账号实例：用户插件目录中的唯一 slug，引用 `template`；保留旧路径兼容已有账号。
- API 配置：`apiBaseURL`、`refreshApiKey`、协议、模型、提示词；端点统一由 `APIEndpoint` 计算。
- 额度配置：`quotaMode` 为 `none`、`endpoint` 或 `script`，独立 `queryUrl`、`queryKey`、网页 Token、Cookie。
- 凭证：兼容旧文件读入，新的写入为 schemaVersion 2，文件权限 0600。显式清除 API Key 不得回退使用额度凭证。
- 查询调度与模型调用使用不同执行槽，按账号隔离；保存不立即发送请求。
- HUD：账号 slug 是动态输出键，显示名只负责呈现，供应商类型名不再承担账号身份。

## 交互方向

主窗承载账号管理，账号列表与详情持续可见；详情围绕 API 连接、可选额度查询、调用计划和展示开关组织。菜单栏用于快览和进入账号，悬浮窗用于持续查看实际额度窗口。

主窗/悬浮窗保持单例和位置记忆，关闭和重新打开行为一致；菜单栏单击开关快览，双击切换悬浮窗，右键提供常用操作。所有按钮有可见结果，错误快照标明旧值。API 测试和额度查询分别反馈结果。

## 验证重点

- 创建/编辑/清除两组凭证互不影响；没有额度查询时仍能测试和配置调用计划。
- 同类型多账号的凭证、缓存、请求和 HUD 键隔离。
- 复制不继承凭证或运行态；保存、取消、关闭、切换账号保持可预期状态。
- 自定义查询准确使用用户指定 URL，不拼接假定的 billing 地址。
- 未返回的窗口/重置时间保持未知；动态窗口在三个展示面一致。
- 原生单击/双击/右键、X/Esc/Cmd-W、最小化/重开、浅色/深色、窗口最小尺寸。
- 使用 swiftly 构建和测试；以离线凭证及请求替身验证，不以自动测试消耗用户真实账号额度。
