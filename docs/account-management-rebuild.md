# TokenHUD：供应商账号三层需求与技术契约

账号状态过滤：概览提供全部、启用、关闭、账号异常及启用且正常过滤；侧栏使用独立条件，默认仅列启用且正常账号。过滤仅影响展示，不改变查询、调用计划或账号开关，也不因当前账号被筛除而丢弃未保存草稿。账号健康与开关、最近请求结果独立：配置缺失或无效、明确的 API 模型／接口配置错误、明确认证失败或过期才归异常；未查询、网络超时、断连、DNS、5xx、429、暂时解析失败及繁忙不据此认定账号损坏。调用与用量查询按各自最新证据恢复，未保存草稿的测试不影响已保存账号健康。仅查询类型无模型配置、未启用的计划缺少模型，不应被误判异常。

更新：2026-11-04。本文是当前需求、技术职责和验收的权威入口，以用户最新三层口径为最高依据，替代 2026-10-30／2026-10-31 文档中与之冲突的设计。本文规定目标行为，不等于这些行为已经完成或所有供应商已经真实联通。

历史交付证据见 [2026-10-31 验证记录](account-management-verification.md)。本轮最终实现版本、执行结果和未验项由主线程据实际证据补充；旧测试通过不能证明新契约通过。

## 一、核心模型：一套基础接入，两项派生能力

```text
供应商账号
└─ 基础模型接入：Auth 认证调用 / API Key 调用
   ├─ 用量查询：统一继承同一认证 → 真实额度与窗口状态 → App / HUD
   └─ 定时 API 调用：复用基础接入 → 尝试主动开启动态 5h 窗口
```

供应商类型与账号实例分开：类型声明端点、协议、认证适配和解析能力；账号实例保存自己的身份、基础接入、计划、缓存与展示偏好。同一类型可有多个账号。

“账号之间隔离”与“同一账号内共享基础认证”同时成立：账号 A 不得读写账号 B 的凭证或快照；账号 A 的模型调用与用量查询统一复用 A 的同一认证上下文。

## 二、第一层：基础模型接入

| 模式 | 目标行为 | 当前边界 |
| --- | --- | --- |
| Auth 认证调用 | 使用账号已有授权身份及有效调用凭证，供模型目录、调用和用量查询共同使用 | 当前范围只读既有本机 CLI／JSON 授权来源；编辑时必须可直接填写 `auth.json` 路径，也可通过文件选择器选择，留空采用供应商类型默认来源。读取来源、当前身份、失效与不可读原因必须可见。App 浏览器 OAuth 登录不是已实现能力，不提供假登录按钮，不写回外部授权文件或擅自刷新 `refresh_token`。 |
| API Key 调用 | 使用该账号配置的 API Key，供模型调用及支持的用量查询共同使用 | Key 遮罩、替换和明确清除；保存不发请求；清除或认证失效阻断依赖该认证的操作，不能偷偷回退其他账号或旧网页凭证。 |

基础接入统一处理账号身份、认证来源、接口地址、调用协议及模型选择。Auth 不是“为了查询额度另外粘贴网页 accessToken”的别名，OpenAI／Anthropic 是调用协议，也不是第三种认证模式。

供应商模板可以固定其地址和协议；通用账号允许配置兼容接口。具体供应商是否支持某种授权调用、模型及端点，须有适配与验证证据；不能由“读到了 token”推断“可以调用任意 API”。

## 三、第二层：用量查询

1. 统一继承第一层的同一账号、同一认证来源：Auth 账号沿用授权上下文，API Key 账号沿用 API Key。不提供独立查询认证模式或额外 Key／Token／Cookie 配置区。
2. 查询地址、请求格式和返回解析可以与模型调用不同，由供应商适配声明；继承认证不等于复用模型调用 URL，也不等于拼接猜测的 billing 路由。
3. 旧网页独立查询认证不再是当前启用方案，也不作为用户选项或回退路径。保存时须清理旧查询字段，同时保留基础 API Key 和授权文件引用；无需用户手工删除旧数据。
4. 无查询接口时仍可管理基础接入和调用计划；界面明确“未接入／不支持／未配置”的实际原因，不伪装成一直加载中。
5. 仅展示供应商实际提供的窗口与单位：5h、周、月或其他窗口都可缺失。缺失不是 0%；重置时间未知时不能补成“请求时间 + 5h”。真实重置时间可以用于倒计时。
6. 查询失败只保留同账号、身份关联明确的旧快照，并显示旧值、最近成功时间及本次错误。窗口到点或调用成功都不是额度已经重置的证据。

[网页查询契约](provider-web-query-contracts.md) 仅保存旧网页／Console 解析的历史取证与离线样本，不再是当前启用方案，不定义本层认证或配置要求。

## 四、第三层：定时 API 调用

业务目的是主动安排“首次使用后开始计时”的动态 5h 窗口，使工作时段有更多机会使用套餐额度。它不是强制 reset、余额刷新，也不只是连通性测试。

例如工作时间为 09:00–18:00，在确实采用首次调用后计时 5h 的供应商上，可配置 05:00／10:00／15:00 小请求，尝试分别形成 05:00–10:00、10:00–15:00、15:00–20:00 的窗口，从而在工作时段获得利用三个窗口的机会。这只是策略示例，不是对任何供应商机制、成功开窗或额度可用性的保证。

- 调度复用第一层接入，使用已保存、明确授权启用的计划；不另存一份调度 Key。
- 配置账号、执行时间、目标模型和最小请求；测试入口用于人工验证同一调用链。调度模型必须适用于目标套餐／用量池并能触发目标窗口，轻量、低成本是在此前提下的选择条件。
- 模型列表与推荐是基础接入的辅助能力。仅凭 `mini`／`flash` 等名称选型，不足以证明适用目标套餐、能触发窗口或价格最低；证据不足时须明示，不自动测试或启用计划。
- 有用量查询能力时，目标流程为“发送请求 → 查询该账号用量 → 根据真实结果验证窗口状态”；没有查询能力时，只报告调用结果与窗口状态未知。
- 已经运行的窗口不能靠重复调用强行重置。重复执行、失败和超时不能通过无条件补发掩盖；结果须区分成功、失败、跳过与不确定。
- 新计划默认关闭；保存、切页、导入和复制不能隐式发送模型请求。只读 Auth 来源由外部工具完成登录／续期，凭证不可用时记录原因，不擅自改外部来源。

## 五、技术职责与扩展边界

以下对象共同承担三层职责。账号配置沿用 schema 3 目标，不另增版本名称：`authMode` 选择 `apikey`／`auth`，用量认证统一继承基础接入；`authCredentialFile` 仅保存只读授权来源引用，必须支持用户编辑／选择路径，留空采用类型默认来源。供应商类型声明授权字段映射、默认来源、调用／模型端点和查询地址／请求头。旧查询字段的读取、清理及必要的内存桥接由后端实现决定，不能据此恢复独立查询用户选项，也不能在清理时丢失基础 Key 或授权文件引用。

`ProviderAuthentication.resolveCall`／`resolveQuota` 为一次操作生成有效认证快照；测试确认与发送复用同一内存快照，不因期间切换登录而改变请求身份。解析后的 Auth 快照禁止作为 API Key 配置落盘。查询脚本通过 0700 临时目录内的 0600 文件接收兼容快照，结束后清理；外部 CLI 授权文件保持只读。

GPT/Codex Auth 的调用／订阅模型端点与 API Key 模式的基础 API 地址应由类型分别声明；GLM 用量查询继承基础 Key，使用对应官方用量 API，不保留网页 JWT 用户模式。上述要求的实现及验证结果须由本轮实际证据确认，不能由离线传输验证推断真实订阅联通或目标模型套餐已在线验证。

| 职责 | 现有对象／入口 | 契约 |
| --- | --- | --- |
| 类型声明与加载 | `ProviderManifest`、`ProviderRegistry`、`providers/<type>/manifest.json` 和 `fetch.sh` | 协议、端点、认证来源及解析差异留在类型声明／适配；新增供应商不改主框架，不加供应商 slug switch。 |
| 账号配置与认证访问 | `ProviderConfigStore` 及基础认证适配 | 按账号管理 Auth／API Key；同账号两项能力统一共享基础认证，只读 CLI／JSON 来源；保存时清理旧查询字段并保留基础 Key 与授权文件引用，不提供额外查询凭证配置区。 |
| 草稿与用户动作 | `SettingsModel`、连接编辑／详情 | 基础接入、用量查询、定时调用分区清楚；草稿测试使用点击时配置，保存和取消不偷发请求，缺失能力有准确原因。 |
| 用量执行与标准化 | `DataEngine`、`ProviderRunner`、供应商脚本 | 用当前账号认证和相关版本查询；输出真实窗口和快照，防止迟到回包串账号。 |
| 模型调用与计划 | `RefreshTrigger`、`DataEngine` 的计划检查 | 手动和计划复用认证及调用链；调用与额度查询是不同动作，并发、去重和结果按账号记录。历史 `refresh` 命名不代表强制重置额度。 |
| 展示投影 | 主窗、菜单快览、悬浮窗、`HUDSync`、状态栏脚本 | 消费同一标准化事实，不各自造额度；展示开关不等于任务启停。 |

账号保留独立稳定标识、配置、缓存、任务状态和展示偏好；复制可复用非敏感结构，但新实例不得继承另一账号的运行态或隐式启用计划。App 自有凭证文件保持受限权限，HUD 不复制认证秘密。

## 七、内置供应商逐项核对

| 类型 | 当前基础接入能力 | 用量认证与接口 |
| --- | --- | --- |
| GPT | Auth；API Key 也可用于独立的 OpenAI API 调用 | ChatGPT/Codex 订阅用量只支持 Auth，同一文件解析出的 token/accountId 调用 wham；API Key 不能用于该订阅查询 |
| GLM | API Key | 同一基础 Key，官方 monitor/usage/quota/limit，Authorization 为裸 Key |
| Cline | API Key | 同一基础 Key，官方 usage-limits，Bearer |
| Ollama | API Key | 同一基础 Key，balance，Bearer |
| OpenCode Go | API Key | 同一基础 Key，Zen Go usage，Bearer |

Auth 选项只在类型声明授权来源时可用；未声明来源的类型禁用并标明未接入，不能以可选 UI 假装已经支持。编辑与详情须展示统一解析器的真实用量认证原因，不能把不支持认证模式一律说成 Key 配错。支持 Auth 的类型继续允许自定义授权文件路径。

本节五家是扩展前的历史逐项核对；当前内置类型与真实能力以[供应商目录](provider-catalog.md)及下节为准。本次逐项核对覆盖五家的 manifest、fetch 启动脚本、临时快照及实际 mjs 请求。Ollama/OpenCode Go 源码仍有旧页面分支，但当前 App 快照先清 Cookie/token 再投影基础认证，不能因此误报当前路径仍在读取独立凭证。五家均有离线实际适配器请求测试，设置相冲突的旧环境来源，验证只读指定快照、使用准确 URL/Header，不发送 Cookie，也不读取另一个账号。

增量验证：[239 项 Swift 回归](../.build/all-supplier-auth-tests.log)、[11 项 Node 回归](../.build/all-supplier-adapters.log)、[Release 构建](../.build/all-supplier-release.log)通过。本次原生编辑测试进程未产出完整汇总，不按退出码 0 计为成功；不沿用前轮 GUI 通过数作为本次新证据。未使用真实凭证或发送真实模型请求。

## 八、供应商目录扩展：当前资源能力

当前[供应商目录](provider-catalog.md)主表有72个去重候选：55个已实现查询资源、17个不启用。按实际manifest中的 `refreshUrl` / `authCallUrl` 核对，22个声明查询加模型调用，33个仅查询。保持原有 `gpt`、`glm`、`cline`、`ollama`、`opencode-go` 五个slug；资源存在只证明源码接线，不能证明供应商账号联通或动态窗口机制。

用户路径为“添加账号 → 搜索并选择内置类型 → 名称 + 基础API Key或填写／选择Auth文件 → 保存”，默认查询由类型提供，不要求用户填写查询脚本、独立查询Token或Cookie。模板新增不会自动创建账号。类型的认证模式以 `quotaAuthModes` 为准，Auth只读来源由 `credentialSource` 的主映射、`alternatives` 与 `contextPaths` 声明；留空仅在存在默认来源时有效。已支持明文JSON导出不等于自动导入原生Keychain、SQLite、TOML或加密客户端数据库；无默认来源必须明确选择已支持格式的文件。

仅查询类型尚未实现模型调用协议，模型测试和调度应明确不可用，不得误报为漏填Key。支持模型调用的新模板默认模型为空，用户必须选定目标套餐／用量池实际可用的模型，计划仍默认关闭。浏览器OAuth、自动Token刷新和外部授权写回不在当前能力内。

显示遵循供应商原始单位：多币种余额分币种展示，period balance和钱包不制造百分比、总上限或reset；缺字段保持未知，到期不等于自动重置。旧缓存只能由核心在同账号身份关联明确时继承，适配器错误不能把另一账号的磁盘缓存重新带回。

本轮最终Swift、Node、构建和安装结果由主线程据实际日志统一补充，不合并不同suite为猜测总数。真实Auth/APIKey联通、套餐模型归属、供应商窗口机制和实际客户端来源导入须逐项留证；离线保存／格式回归不能替代这些验收。

最新纳入规则：没有真实额度查询的供应商不加入内置类型。Groq仅提供速率响应头，改为不启用，55个固定额度类型之外保留自定义OpenAI兼容／Anthropic兼容两个通用入口；自定义仅支持基础API Key，不支持Auth文件。用户提供完整额度URL，默认HTTP GET并复用同一基础Key，按通用标准JSON normalize契约解析；不添加独立查询认证、不猜测billing路径、不要求用户自写查询脚本。自定义入口不计入72个固定品牌候选。

## 九、导入账号：实时只读来源引用

导入按原来源主键去重；对声明稳定身份规则的 Auth 类型（当前 GPT/Codex），再按命名空间、签发方、账号主体和 workspace 的一致证据进行跨来源去重。workspace 可来自声明的请求头或 JWT claim，二者冲突则不匹配；缺失身份依据时不按邮箱、显示名或 Token 字节猜测。预览默认跳过，提交前重新读取来源并在同进程导入锁内复查；不自动删除或合并已有账号及其计划、显示设置。账号列表的来源筛选与搜索、状态筛选叠加，只影响显示。

导入不复制Auth或API Key。`ProviderSourceReference` 保存 `source/path/recordId` 及可选 `providerId/collection/credentialProviderId`；文件按原路径读取，SQLite用只读连接按记录主键和类型精确匹配。每次操作解析来源为本次内存认证快照，不把解析后的Key落入账号文件；来源缺失、删除、类型变化或身份映射不唯一时明确失败，不使用旧复制凭证。四种来源并不代表各来源的全部供应商均已适配。

| 来源 | 绑定与支持边界 |
|---|---|
| 9router | `providerConnections.id + provider`；Auth/API Key结构必须符合对应模板。通用兼容记录只在显式协议、地址有效时接入。 |
| cc-switch | 当前仅Claude，按 `id + app_type` 复合身份读取；其它命名空间预览为不支持，不跨类型取同名主键。 |
| CPAMP | 引用既有CPA授权文件，以文件名和 `type` 校验；仅已有模板支持的认证格式可导入，不复制JSON秘密或触发refresh。 |
| Magpie | 主Key引用 `providers.json` 的原providerID并跟随当前Key；额外Key以SHA256前10位十六进制指纹定位槽，删除或更换后不可用，不自动改指向别的Key。插件保留完整账号slot、实际providerID（可含 `-plugin`）及credential providerID，并结合 `plugin-providers.json` 验证唯一归属和账号一致性。原生 `logins.json` 中有内联Auth快照且匹配模板时，按唯一 `id + agent` 只读绑定；无快照、需Keychain或续期的记录仍不支持。原生 `on` 仅为Magpie备用路由标记，不控制QuotaNest启用状态。新Auth引用另存稳定账号证据的哈希，账号变化即拒绝，不随默认slot改用另一用户；访问令牌轮换不复制落盘。ZCode Start只按声明路径读取 `refresh.jwt/device`，不把Coding plan Key当Start JWT，不信任源base覆盖模板查询地址。默认根目录为绝对 `XDG_CONFIG_HOME` 下的magpie，否则为 `~/.config/magpie`；UI允许显式选择含配置文件的portable根目录。 |

导入的来源配置只读：认证、接口地址和来源计划不能改写；允许本地显示名覆盖、本地启停、显示、查询和删除关联，均不修改来源。对已声明模型调用能力的类型，可选择或拉取临时测试模型，经确认发送一次请求；临时模型只作用于该次测试，不保存到来源或计划。仅额度查询的类型仍不开放模型调用按钮。通用来源账号每次使用源记录当前显式协议与URL，内置模板则保持类型固定协议；URL展示去除userinfo与query，避免带出秘密。旧 `origin` 导入账号锁定，可通过重扫转换为来源引用，保持原slug并清除旧本地Key与不再匹配的缓存。

来源记录内容形成 `sourceRevision` 摘要，用于隔离旧缓存、源变更和迟到回包；来源删除不继续展示旧成功状态。HUD只记录安全依赖路径及mtime（数据库含WAL、插件含身份映射依赖），不解析秘密数据库。最终回归结果由主线程统一汇总；这里不将源码接线或扫描成功视为真实供应商联通、原生Keychain导入或登录续期已验证。

额度查询与来源同步是两套时钟：已启用、已配置账号的后台额度查询间隔统一为不超过 300 秒，模板或用户原有更短间隔保留，旧的一小时等覆盖值按五分钟上限生效；App 休眠或断网期间不承诺硬实时。每次额度查询失败后重试两次（总共最多三次，1 秒／2 秒退避），同账号整个序列单飞；取消、来源身份或凭证版本变化时停止并丢弃迟到结果。最终失败保留身份和版本仍一致的旧成功值及成功时间，更新失败状态、尝试时间及次数，界面明确旧值。手动查询停用账号不恢复后台计划；模型调用没有新增自动重试。删除导入账号仅移除 QuotaNest 本地关联、自有配置与缓存及本应用管理的 HUD 显示，不注销或修改外部来源账号／凭证／配置。

来源自动同步默认开启，在App运行期间每小时检查一次；启动及休眠恢复后的到期检查复用同一调度，关闭自动同步后仍可点击“立即同步”。概览与导入页展示开关、上次检查与本次结果；账号详情保留当前及原始记录ID，并显示需要人工处理的问题。同步只检查已导入的引用，不自动新增或删除账号，不调用模型或消耗额度，不把认证写回来源。

原记录仍存在时先验证类型、模式和协议并刷新非明文身份摘要；原主键消失时，只在同一来源容器与命名空间中以完整凭据摘要的唯一匹配、或Magpie明确且唯一的was改名关系订正ID。保留原始记录与providerID，账号slug、本地启停、显示和顺序保持不变。多个候选、无可信摘要、类型或协议变化都不猜测；ID与Token同时变化且没有可信关联时需要人工重新扫描。首次为旧有效引用登记摘要不算ID更正，之后写入失败、来源在扫描后变化或账号被删除时不提交部分结果。
