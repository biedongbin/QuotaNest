# TokenHUD：供应商账号三层需求与技术契约

更新：2026-11-04。本文是当前需求、技术职责和验收的权威入口，以用户最新三层口径为最高依据，替代 2026-10-30／2026-10-31 文档中与之冲突的设计。本文规定目标行为，不等于这些行为已经完成或所有供应商已经真实联通。

历史交付证据见 [2026-10-31 验证记录](account-management-verification.md)。本轮最终实现版本、执行结果和未验项由主线程据实际证据补充；旧测试通过不能证明新契约通过。

## 一、核心模型：一套基础接入，两项派生能力

```text
供应商账号
└─ 基础模型接入：Auth 认证调用 / API Key 调用
   ├─ 用量查询：通常继承同一认证 → 真实额度与窗口状态 → App / HUD
   └─ 定时 API 调用：复用基础接入 → 尝试主动开启动态 5h 窗口
```

供应商类型与账号实例分开：类型声明端点、协议、认证适配和解析能力；账号实例保存自己的身份、基础接入、计划、缓存与展示偏好。同一类型可有多个账号。

“账号之间隔离”与“同一账号内共享基础认证”同时成立：账号 A 不得读写账号 B 的凭证或快照；账号 A 的模型调用与用量查询则通常应复用 A 的同一认证上下文。

## 二、第一层：基础模型接入

| 模式 | 目标行为 | 当前边界 |
| --- | --- | --- |
| Auth 认证调用 | 使用账号已有授权身份及有效调用凭证，供模型目录、调用和用量查询共同使用 | 当前范围只读既有本机 CLI／JSON 授权来源；读取来源、当前身份、失效与不可读原因必须可见。App 浏览器 OAuth 登录不是已实现能力，不提供假登录按钮，不写回外部授权文件或擅自刷新 `refresh_token`。 |
| API Key 调用 | 使用该账号配置的 API Key，供模型调用及支持的用量查询共同使用 | Key 遮罩、替换和明确清除；保存不发请求；清除或认证失效阻断依赖该认证的操作，不能偷偷回退其他账号或旧网页凭证。 |

基础接入统一处理账号身份、认证来源、接口地址、调用协议及模型选择。Auth 不是“为了查询额度另外粘贴网页 accessToken”的别名，OpenAI／Anthropic 是调用协议，也不是第三种认证模式。

供应商模板可以固定其地址和协议；通用账号允许配置兼容接口。具体供应商是否支持某种授权调用、模型及端点，须有适配与验证证据；不能由“读到了 token”推断“可以调用任意 API”。

## 三、第二层：用量查询

1. 通常继承第一层的同一账号、同一认证来源：Auth 账号沿用授权上下文，API Key 账号沿用 API Key。常规流程不要求再填第二套查询 Key。
2. 查询地址、请求格式和返回解析可以与模型调用不同，由供应商适配声明；继承认证不等于复用模型调用 URL，也不等于拼接猜测的 billing 路由。
3. 网页 accessToken／Cookie 是历史特殊兼容。旧 GLM 因缺少可用 API 查询额度而采用此路，不再作为默认配置模式或接入前提，基本可舍弃。保留旧适配时应明确标为兼容入口，不把它提升为常规第二套认证。
4. 无查询接口时仍可管理基础接入和调用计划；界面明确“未接入／不支持／未配置”的实际原因，不伪装成一直加载中。
5. 仅展示供应商实际提供的窗口与单位：5h、周、月或其他窗口都可缺失。缺失不是 0%；重置时间未知时不能补成“请求时间 + 5h”。真实重置时间可以用于倒计时。
6. 查询失败只保留同账号、身份关联明确的旧快照，并显示旧值、最近成功时间及本次错误。窗口到点或调用成功都不是额度已经重置的证据。

[网页查询契约](provider-web-query-contracts.md) 仅保存旧网页／Console 兼容解析的取证与离线样本，不定义本层默认认证方案。

## 四、第三层：定时 API 调用

业务目的是主动安排“首次使用后开始计时”的动态 5h 窗口，使工作时段有更多机会使用套餐额度。它不是强制 reset、余额刷新，也不只是连通性测试。

例如工作时间为 09:00–18:00，在确实采用首次调用后计时 5h 的供应商上，可配置 05:00／10:00／15:00 小请求，尝试分别形成 05:00–10:00、10:00–15:00、15:00–20:00 的窗口，从而在工作时段获得利用三个窗口的机会。这只是策略示例，不是对任何供应商机制、成功开窗或额度可用性的保证。

- 调度复用第一层接入，使用已保存、明确授权启用的计划；不另存一份调度 Key。
- 配置账号、执行时间、目标模型和最小请求；测试入口用于人工验证同一调用链。调度模型必须适用于目标套餐／用量池并能触发目标窗口，轻量、低成本是在此前提下的选择条件。
- 模型列表与推荐是基础接入的辅助能力。仅凭 `mini`／`flash` 等名称选型，不足以证明适用目标套餐、能触发窗口或价格最低；证据不足时须明示，不自动测试或启用计划。
- 有用量查询能力时，目标流程为“发送请求 → 查询该账号用量 → 根据真实结果验证窗口状态”；没有查询能力时，只报告调用结果与窗口状态未知。
- 已经运行的窗口不能靠重复调用强行重置。重复执行、失败和超时不能通过无条件补发掩盖；结果须区分成功、失败、跳过与不确定。
- 新计划默认关闭；保存、切页、导入和复制不能隐式发送模型请求。只读 Auth 来源由外部工具完成登录／续期，凭证不可用时记录原因，不擅自改外部来源。

## 五、技术职责与扩展边界

以下对象共同实现三层职责。当前账号配置为 schema 3：`authMode` 选择 `apikey`／`auth`，`quotaCredentialMode` 选择默认 `inherit` 或历史 `legacy`，`authCredentialFile` 仅保存只读授权来源引用。供应商的 `credentialSource` 声明 JSON 字段映射、环境目录及旧文件指针兼容键；Auth 专用调用／模型端点和继承查询地址／请求头也由类型声明。

`ProviderAuthentication.resolveCall`／`resolveQuota` 为一次操作生成有效认证快照；测试确认与发送复用同一内存快照，不因期间切换登录而改变请求身份。解析后的 Auth 快照禁止作为 API Key 配置落盘。查询脚本通过 0700 临时目录内的 0600 文件接收兼容快照，结束后清理；外部 CLI 授权文件保持只读。

GPT/Codex Auth 使用已声明的 Responses 调用和订阅模型端点，API Key 模式仍使用基础 API 地址；GLM 继承查询使用同 Key 的官方用量 API，旧网页 JWT 保留在兼容模式。接口适配经过离线传输验证，不代表真实订阅联通或目标模型套餐已在线验证。

| 职责 | 现有对象／入口 | 契约 |
| --- | --- | --- |
| 类型声明与加载 | `ProviderManifest`、`ProviderRegistry`、`providers/<type>/manifest.json` 和 `fetch.sh` | 协议、端点、认证来源及解析差异留在类型声明／适配；新增供应商不改主框架，不加供应商 slug switch。 |
| 账号配置与认证访问 | `ProviderConfigStore` 及基础认证适配 | 按账号管理 Auth／API Key；同账号两项能力默认共享基础认证，只读 CLI／JSON 来源；不以旧 `queryKey` 等字段的存在维持错误的常规双凭证设计。 |
| 草稿与用户动作 | `SettingsModel`、连接编辑／详情 | 基础接入、用量查询、定时调用分区清楚；草稿测试使用点击时配置，保存和取消不偷发请求，缺失能力有准确原因。 |
| 用量执行与标准化 | `DataEngine`、`ProviderRunner`、供应商脚本 | 用当前账号认证和相关版本查询；输出真实窗口和快照，防止迟到回包串账号。 |
| 模型调用与计划 | `RefreshTrigger`、`DataEngine` 的计划检查 | 手动和计划复用认证及调用链；调用与额度查询是不同动作，并发、去重和结果按账号记录。历史 `refresh` 命名不代表强制重置额度。 |
| 展示投影 | 主窗、菜单快览、悬浮窗、`HUDSync`、状态栏脚本 | 消费同一标准化事实，不各自造额度；展示开关不等于任务启停。 |

账号保留独立稳定标识、配置、缓存、任务状态和展示偏好；复制可复用非敏感结构，但新实例不得继承另一账号的运行态或隐式启用计划。App 自有凭证文件保持受限权限，HUD 不复制认证秘密。

## 六、验收清单与状态

本轮已执行 236 项 Swift 测试、8 项 Node 脚本测试，另在独立进程执行原生编辑按钮 1 项及窗口／悬浮尺寸 3 项，均通过；Release 构建通过。默认跳过的 GUI 项不算已验，原生计数来自单独启用后的最终汇总。日志：[Swift](../.build/shared-auth-integration-tests.log)、[适配器与 HUD](../.build/shared-auth-provider-tests.log)、[原生编辑](../.build/shared-auth-native-editor.log)、[窗口与紧凑尺寸](../.build/shared-auth-native-window.log)、[Release](../.build/shared-auth-release.log)。

| 条目 | 必须观察到的结果 | 本轮状态 |
| --- | --- | --- |
| Auth 基础接入 | 受支持的只读来源；同一身份快照用于调用／查询；不写外部 auth 或持久化解析 token | 离线通过，包括真实发送函数＋URLProtocol 的 Responses 请求／响应闭环；真实订阅联通未验 |
| API Key 基础接入 | 调用和查询继承同 Key；替换／清除不回退旧 Key | 离线通过，包括自动查询不需要第二 Key、清除及认证变化回归 |
| 查询地址与解析 | URL 可以不同、基础认证一致，字段按真实返回解释 | GLM 裸 Key 官方地址及真实周期解析、GPT 同身份快照离线通过；真实服务未在线复验 |
| 旧网页兼容 | 旧凭证保留且显式 legacy，不作为新账号默认前提 | Schema 2→3、旧授权文件指针及新模板默认继承回归通过；旧网页未重新在线验收 |
| 调度与目标套餐 | 固定时刻调用，成功后查询实际窗口，不把 HTTP 成功当 reset | 调度／去重及调用链离线通过，成功后查询已接线；目标套餐和真实开窗机制仍待实号验证 |
| 多账号隔离 | 各账号配置／缓存／回包独立，共享认证只发生于同账号两项能力之间 | 离线通过，覆盖源切换／删除、停用详情缓存回退和 HUD 旧桶拒绝 |
| 编辑／详情 | 基础接入、查询继承、5h 调度分区清楚，保存／取消无隐式模型调用 | 模型／草稿回归通过，原生编辑按钮与单例窗口生命周期通过 |
| 展示一致性 | 同一快照、缺失与旧值明确、仅 API 账号不假装加载 | HUD 读端与 API-only 回归通过；紧凑行距 12→3、行内纵向 padding 2→1、底部 12→4，实际面板尺寸回归通过 |

本轮没有使用真实凭证发起模型测试。Auth 在线联通、外部授权续期、模型所属套餐和供应商真实窗口机制仍须逐供应商留证。退出 App 后 HUD 不自行发起新增查询，但已能拒绝授权来源变更／消失后的旧桶；睡眠／离线错过计划不擅自补发。
