# QuotaNest A/B/C 架构与需求契约

依据：2026-11-09 用户澄清。本文规定系统职责、运行依赖和交互边界，是 A/B/C 架构需求的权威入口；代码设计见 [Claude Code HUD 程序架构](claude-code-hud-design.md)，账号业务细则见 [账号管理需求](account-management-rebuild.md)。需求约束不等于每项行为已经实机验证，历史方案不得覆盖用户最新要求。

## 1. A、B、C 分别是什么

| 组件 | 定位 | 负责什么 | 不承担什么 |
| --- | --- | --- | --- |
| A：Magpie、9router、cc-switch、CPAMP 等 | 外部凭证来源 | 持有和维护各自的账号记录、API Key、Auth 授权；由来源工具处理登录与续期 | 不要求 A 向 B 或 C 推送额度；A 自身是否提供额度功能不影响本架构 |
| B：QuotaNest | 独立的 macOS 额度管理应用 | 管理本地账号引用；直接读取 A；自行查询供应商、维护 B 缓存；提供菜单栏、悬浮窗、设置、来源同步及已授权的模型调用计划 | 不是 C 的查询服务、缓存服务器或运行守护进程 |
| C：Claude Code HUD | 独立的 Claude Code 状态栏程序 | 由 Node 直接读取 A 的指定记录；自行查询供应商、维护 C 缓存；在 Claude Code 中展示用量 | 不调用 B 的 CLI，不读取 B 的查询结果，不等待 B 同步，不承担 B 的模型调用计划 |

B 和 C 是两个凭证消费者与用量查询者。这里的 A/B/C 是系统角色，与业务文档中的“基础接入／用量查询／定时调用”三层能力是两种不同划分。

```text
A 的凭证记录 ──只读──→ B ──独立查询──→ 供应商用量 API
                         └── B 缓存 → 菜单栏／悬浮窗／设置

A 的凭证记录 ──只读──→ C ──独立查询──→ 供应商用量 API
                         └── C 缓存 → Claude Code HUD

用户点击 B 的「写入 Claude Code HUD」
              └── 一次性写入 C 的脚本、来源引用、查询与显示配置
```

运行时 B 与 C 之间没有查询请求、结果同步或缓存回传。共享供应商适配源码不等于共享进程或运行状态；导出后 C 使用自己的脚本副本。

## 2. 解耦必须满足的行为

1. 完成一次导出后，B 退出或停止查询，C 仍能在 Claude Code 渲染时自行读取来源、查询和更新。
2. Claude Code 未启动、C 未导出或 C 查询失败，不影响 B 查询和悬浮窗。
3. B 与 C 各自承担请求、节流、错误处理、身份校验和缓存。两边取数时间不同，短时间显示不同数值是允许的，不要求强行同步。
4. B 与 C 对 A 均只读。不修改外部账号、切换 A 的默认账号、写回授权或擅自执行刷新令牌操作。源凭证续期由来源工具负责。
5. C 的失败必须依据自己的来源解析或请求结果；不能显示“等待 QuotaNest 查询”作为正常运行前提。
6. 不以 A 整个文件的修改时间判定当前账号额度失效。无关记录变化不能造成当前账号反复隐藏额度。

“独立”仍有明确前提：C 需要 Node、已导出的脚本、可读来源和供应商网络连接；它不意味着离线也能获得新额度，或自动支持任意来源格式。

## 3. B → C 唯一操作：写入 Claude Code HUD

唯一入口是用户主动点击 **「写入 Claude Code HUD」**。该动作按 B 当前已保存的账号、启用与显示选择、顺序，生成 C 可以独立执行的配置和脚本。

| 用户动作或后台事件 | B 的行为 | 对现有 C 的影响 |
| --- | --- | --- |
| 启动、升级或安装 B | 初始化或更新 B 自己的运行时 | 不自动导出 |
| B 手动／后台查询额度 | 更新 B 缓存及界面 | 不写 C 缓存或配置 |
| B 每小时来源同步／立即同步 | 检查 B 已导入引用，按规则修正本地关联 | 不修改 C 的引用 |
| 保存、改名、排序、勾选 HUD 显示、启停账号 | 保存 B 本地状态，提示待写入 | 下次显式导出才更新 C |
| 在 B 删除账号 | 删除 B 本地关联和自有数据，保留 A | 现有 C 继续按上次导出运行；下次显式导出才移除受 B 管理的条目 |
| 点击「写入 Claude Code HUD」 | 校验并写入独立运行包，反馈成功或错误 | 更新 C 配置；后续渲染使用新配置 |

导出包含运行时脚本、账号查询包装脚本、来源引用、认证格式映射、查询地址与请求头模板、显示标签与顺序，以及 Claude Code 的状态栏接线。导出不查询额度、不发送模型请求、不解析并复制导入账号的实时令牌。

导出应保留第三方条目和无关 Claude Code 设置；识别应用管理的条目不能只依赖显示名。修改 B 的待导出配置不等于修改 C，UI 必须提供可见的待写入提示。导出失败必须明确反馈，不把部分成功报告成完整成功。当前写入与回滚的具体边界见设计文档。

## 4. 三套独立时钟

| 机制 | 所属组件 | 触发与用途 |
| --- | --- | --- |
| 来源记录同步 | B | 默认开启，App 运行时每小时检查已导入引用；启动／恢复时检查是否到期；支持立即同步。不会自动导入新账号，不负责替 C 取数 |
| 额度轮询 | B | 已启用且已配置账号按自身调度查询；当前业务上限为 300 秒，更短间隔保留，休眠／离线不保证实时 |
| HUD 查询节流 | C | Claude Code 每次渲染读取 C 缓存，最近尝试未满 60 秒时不重复查询；到期后由渲染启动后台 worker |

C 没有独立的“每分钟定时器”。没有 Claude Code 渲染，就不承诺自动查询；后台结果在后续渲染中显示。B 的小时级来源同步不能改成 C 的刷新时钟，B 的额度轮询也不能成为 C 的数据来源。

## 5. 凭证、身份和数据归属

| 账号方式 | B 保存的内容 | C 获取凭证的方式 |
| --- | --- | --- |
| 从 A 导入 | 来源路径、记录主键、类型及必要的身份证据 | 导出仅传递引用与格式声明；C 每次查询直接解析 A |
| 独立 Auth 文件 | 外部授权文件引用 | C 按导出的只读路径自行解析 |
| 用户手填 API Key | B 自有凭证配置 | 显式导出时复制到 C 自有的受限 Key 文件；后续 B 改 Key 不自动更新 C |

每个账号用稳定 slug 区分，标签重复不代表同一账号。来源类型、记录或身份不匹配时必须报告不可用，不能回退另一个账号或历史复制的凭证。凭证轮换与账号切换应分别处理；请求过程中认证或配置变化时不得发布过期响应。

B 运行时在 `~/Library/Application Support/QuotaNest/runtime`。B 历史凭证与缓存仍可位于 `~/.claude/hud/` 下，使用 `.*-usage-auth.json` 和 `.*-usage-cache.json`；这是存储布局兼容，不是允许 C 读取 B 缓存。C v2 使用独立的 `.*-hud-cache.json`，手填 Key 使用 `.*-hud-auth.json`。目录重叠时必须按文件归属判断，不能整目录清理或互相覆盖。

A 中同一记录正常更新凭证，C 在下一次允许的查询时直接读取，无需 B 中转。A 的主键改变而 B 同步修正引用后，C 仍保留旧引用；必须再次点击导出，才能把 B 修正的引用交给 C。C 不自动采用 B 的新关联。

## 6. 不得恢复的旧方案

- C 通过 B 的 CLI、IPC 或后台服务获取认证或额度。
- C 只读 B 缓存，把 B 定义成唯一查询者。
- B 每次查询、启动、来源同步或编辑时自动重写 C。
- C 因 A 整文件 mtime 变化隐藏额度，等待 B 重新投影。
- 为了保持两边一致而把 B 的悬浮窗改成读取 C 缓存。
- 将导入账号的实时 token 当作普通 API Key 固化到 C，或把手填 Key 快照当作可实时跟随 B 的引用。

## 7. 架构验收场景

下列为验收要求，执行记录须另附实际版本与结果，不能仅凭文档勾选为通过。

| 场景 | 预期结果 |
| --- | --- |
| 导出后退出 B，再触发 C 的过期缓存查询 | C 直接访问 A 和供应商，更新自己的缓存 |
| 不启动 Claude Code，在 B 查询 | B 照常更新自身界面和缓存 |
| 在 B 查询、改顺序、关闭显示、停用或删除账号 | C 的配置／脚本保持原样，直到显式导出 |
| B 每小时同步修正来源 ID | 仅 B 引用变化；再次导出后 C 才获得新引用 |
| A 修改无关记录 | 当前 C 账号不因整文件时间变化被清空 |
| A 删除绑定记录或切换到不匹配的身份 | C 报告来源问题，不展示另一账号结果 |
| 查询过程中替换配置或凭证 | 旧响应被丢弃，不能污染新配置缓存 |
| C 网络失败 | 仅在绑定仍一致时保留旧成功数据并标记陈旧；不借用 B 缓存 |
| 手填 Key 清空后再次导出 | C 的旧 Key 被空快照覆盖，不继续使用旧秘密 |
| 导出缺少脚本、配置写入失败 | 有明确错误；按实际回滚能力报告状态，不宣称无条件事务原子性 |

当前 v2 导出是目标架构的实现入口；旧内置 HUD 分支仍有兼容路径，不能用其存在为新账号引入共享缓存依赖。兼容范围及未完成边界在 [HUD 程序架构](claude-code-hud-design.md) 中单独说明。
